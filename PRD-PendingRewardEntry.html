一、需求背景与范围

H5「优惠 → 待领取」页面已上线（《客户端-待领取》需求，任务 t104856），用于集中领取需要会员手动领取的活动奖励。目前存在两个问题：

  1. 入口较深，会员需主动进入「优惠 → 待领取」才能发现可领取奖励，容易遗漏；
  2. VIP 奖励与返水同样需要会员手动领取，但未纳入待领取页面，会员需分别进入 VIP 页、返水页领取。

本次需求范围

端改动
站点后台系统管理 → 系统设置 → 站点显示配置，新增「待领取入口」配置（开关、最低展示金额）
H5 前台新增待领取入口：会员存在待领取奖励时显示，点击进入「优惠 → 待领取」
H5 前台 / 后端待领取页面的列表、数量、总金额、一键领取纳入 VIP 奖励与返水

原型：待领取入口原型。

二、名词定义

名词定义
待领取奖励已发放到会员名下、当前可立即领取、需会员手动操作才会进入账户的奖励。系统自动派发到账的奖励不属于待领取奖励。
待领取数量待领取页面列表的记录条数。活动奖励与 VIP 奖励按笔计数，返水合并为 1 条计数（见 6.3）。
待领取总金额待领取页面所有记录的奖励金额之和，即待领取页面顶部「奖金」显示的金额。
待领取入口本需求新增的前台入口，仅在满足 5.1 显示条件时出现，点击进入「优惠 → 待领取」。

四、后台配置

4.1 配置位置

站点后台 → 系统管理 → 系统设置 → 站点显示配置，左侧子菜单新增「待领取入口」，排在「快捷入口」之后。页面底部为「保存」按钮，保存后立即生效，前台在下次触发 5.3 刷新时读取新配置。

4.2 字段规格

字段含义控件必填输入要求说明 / 前台效果
待领取入口是否在前台显示待领取入口开关是开启 / 关闭，默认关闭关闭时前台不显示入口，待领取页面本身不受影响。
最低展示金额待领取总金额大于该值才显示入口数字输入框，前缀 R$否≥ 0 的数字，最多 2 位小数；默认 0.10待领取总金额 > 该值时显示入口，默认即总金额大于 R$ 0,10 时提醒。
为空按 0 处理：只要待领取数量 > 0 即显示入口。
格式错误时提示：「请输入大于等于 0 的金额，最多 2 位小数」。

五、前台：待领取入口

5.1 显示条件

同时满足以下条件时显示入口，任一条件不满足则不显示：

  1. 会员已登录；
  2. 后台「待领取入口」开关已开启；
  3. 待领取数量 > 0（含活动奖励、VIP 奖励、返水，见第六章）；
  4. 待领取总金额 > 最低展示金额（默认 R$ 0,10；为空按 0 处理）。

入口无入场、退场动效：满足条件时直接显示，条件不再满足（如全部领取完毕）时直接隐藏。入口不提供关闭按钮。

5.2 入口形式：首页横条

入口为首页 Banner 下方的横条，仅在首页显示。

项规则
位置首页 Banner 下方、跑马灯上方，通栏，左右边距与 Banner 一致。横条显示时下方内容整体下移；隐藏时恢复原位。
内容左侧礼包图标；中间文案「你有 {待领取总金额} 奖励待领取」，金额按 R$ 格式显示两位小数（如 R$ 12,50、R$ 1.250,00），文案超长时省略号截断；右侧「去领取」按钮。按钮与横条样式以 UI 设计稿为准。
点击点击横条任意位置（含「去领取」按钮）进入「优惠 → 待领取」。
常驻动效循环播放：礼包图标每 3.6 秒摇晃一次；一道扫光每 3.6 秒从左到右划过横条。「去领取」按钮不单独加动效。

5.3 数据刷新时机

以下时机重新读取待领取数量与总金额，并重新判断入口是否显示：

  • 进入首页（含从其他页面返回首页）；
  • 首页下拉刷新；
  • 任一领取成功后（待领取页面一键领取、活动详情页领取、VIP 页领取、返水页领取）。

六、前台：待领取页面奖励范围

6.1 纳入范围总表

奖励纳入条件本次是否改动
救援金、神秘彩金、充值、红包雨活动后台「领取方式」= 手动领取，且奖励当前可领取否，沿用现有逻辑
VIP 奖励见 6.2新增
返水见 6.3新增
会员答谢、签到、首充亏损返利、限时充值返利、助力转盘、幸运转盘、注册引导转盘、自定义不纳入。会员答谢在点击领取时才计算奖励；签到、首充亏损返利在活动内点击后自动发放；其余为自动派发或走各自申请流程否

6.2 VIP 奖励

  • 纳入条件：站点后台「VIP 管理 → 等级奖励记录」中状态为「未领取」的记录，每条记录在待领取列表中显示为一条。
  • 奖励类型：以等级奖励记录的福利类型为准：升级福利、每日福利、每周福利、月度福利。
  • 列表字段：时间 = 奖励生成时间；活动名称 = VIP；奖励 = 福利金额；来源 = 「VIP{等级}{福利类型}」，例如「VIP1 每日奖励」。名称与来源用词沿用我方 VIP 页现有文案。
  • 移出条件：奖励被领取；或按 VIP 管理「领取规则」跨天 / 跨周 / 跨月后被系统回收作废或改为邮件下发，此时该记录立即从待领取列表移出。

6.3 返水

  • 纳入条件：会员存在「领取状态 = 未领取」的返水记录（站点后台「返水管理 → 会员返水记录」）。
  • 合并显示：所有未领取返水在待领取列表中合并为 1 条：时间 = 最近一笔未领取返水的发放时间；活动名称 = 返水；奖励 = 未领取返水金额合计，与返水页「可领取」金额一致；来源 = 实时返水。名称与来源用词沿用我方前台现有文案。
  • 计数：无论未领取返水记录有多少笔，在待领取数量中计为 1。
  • 移出条件：未领取返水全部领取后移出。

6.4 一键领取与状态同步

  • 待领取页面「一键领取（Coletar Tudo）」一次领取列表内全部奖励，包括活动奖励、VIP 奖励、返水；领取结果弹框中的金额为本次实际到账总额。
  • 在待领取页面领取后：VIP 页对应奖励变为已领取，返水页可领取金额清零，活动详情页领取按钮回到不可领取状态。
  • 在 VIP 页、返水页、活动详情页领取后：待领取页面对应记录同步移出，待领取数量与总金额同步更新。
  • 一键领取中部分奖励领取失败时：成功部分正常到账并移出列表，失败部分保留在列表中，弹框提示「部分奖励领取失败，请稍后重试」。

6.5 红点与数量

  • 「优惠 → 待领取」标签红点、待领取数量与总金额均包含 VIP 奖励与返水。
  • VIP 标签、返水标签原有红点逻辑不变。

八、边界与异常

场景处理
待领取数量 / 总金额接口请求失败不显示入口，不提示错误；下次刷新时机重新请求。
入口显示期间，会员在其他页面领完全部奖励回到首页时重新判断，入口隐藏。
点击入口进入待领取页面时，奖励已被领取或已作废待领取页面按最新数据展示；无数据时显示空状态「Sem Registros」。
后台关闭开关或调高最低展示金额前台在下次刷新时机按新配置判断，已显示的入口随之隐藏。
VIP 奖励过期回收或改为邮件下发该记录从待领取列表移出，数量与总金额同步扣减（见 6.2）。
未登录访客不显示入口，不请求待领取接口。
