一、背景与目标

现状：推广渠道管理及官方渠道配置中，「下载按钮」为单一开关，同时控制 H5 首页的顶部横幅与底部安装浮层两个前台组件。运营无法只保留其中一个，也无法针对不同渠道做轻重打扰的差异化投放。

目标：将「下载按钮」拆分为两个相互独立的开关，使顶部横幅与底部安装浮层可分别控制。

范围界定：本次仅做开关控制的拆分。两个组件的样式、文案、内容取值、点击安装后的全部交互流程（已安装唤起 → 浏览器路由 → 安卓 / iOS 安装机制）均保持现状不变，不做任何调整。

二、后台字段变更

2.1 字段结构变化

拆分前

  • 下载按钮　必填
  • ↳ 同时控制顶部横幅 + 底部安装浮层
  • 引导安装　必填
  • ↳ 弹框内容 / 弹框时间点 / 弹框间隔时间 …

拆分后

  • 顶部横幅　必填
  • 底部安装浮层　必填
  • 引导安装　必填
  • ↳ 弹框内容 / 弹框时间点 / 弹框间隔时间 …（不变）

删除原「下载按钮」字段，新增两个独立字段，无父级总开关、无子级嵌套。两个字段在原「下载按钮」所在位置并列展示，顺序为顶部横幅 → 底部安装浮层 → 引导安装。

2.2 字段说明

字段必填控件选项与默认值字段说明
顶部横幅 必填 下拉单选 可选：开启 / 关闭；默认「关闭」 开启后，H5 首页顶部常驻展示下载提示横幅（流布局，将页面内容向下推移，不覆盖页面），含 APP 图标、提示文案、装饰图、安装按钮、关闭按钮；关闭则不展示。不区分登录状态，已登录用户同样可见。落地指向为下载页类时不生效。
底部安装浮层 必填 下拉单选 可选：开启 / 关闭；默认「关闭」 开启后，未登录用户每次进入 H5 首页时从底部弹出安装浮层（带遮罩，覆盖整个页面含顶部横幅），含 APP 图标、含动态域名的说明文案、取消按钮、安装按钮；关闭则不展示。用户登录后浮层隐藏且不再触发。落地指向为下载页类时不生效。

三、关联控制逻辑

3.1 两个开关之间

两者完全独立、无互斥、无父子联动，任一开关的取值不影响另一个的可配置性，四种组合均为合法配置：

顶部横幅底部安装浮层前台表现
开启开启横幅常驻；未登录用户进入首页时浮层弹出，遮罩覆盖横幅，浮层关闭后横幅恢复可见。等同于拆分前「下载按钮 = 开启」。
开启关闭仅横幅常驻，任何情况下不弹浮层。
关闭开启无横幅；未登录用户进入首页时仅弹浮层，浮层关闭后页面无任何常驻安装入口。
关闭关闭两者均不展示，H5 首页无下载入口。等同于拆分前「下载按钮 = 关闭」。

3.2 生效条件（沿用原下载按钮口径）

落地指向顶部横幅底部安装浮层
H5 页类（官网首页 / 官网注册页 / 主域名）✅ 生效✅ 生效
下载页类（仿谷歌页 / 防封下载页）❌ 不生效❌ 不生效

落地指向为下载页类时，两个开关的配置值保留但前台不生效，与原「下载按钮」规则一致。

3.3 顶部横幅的展示规则

  • 不区分登录状态，开关开启即常驻展示，已登录用户同样可见。
  • 用户点击「×」后当次会话不再显示。
  • 用户点击安装按钮并完成安装后，横幅保持可见，不自动隐藏。
  • 底部安装浮层或引导安装弹窗出现时，横幅被遮罩层覆盖但不被关闭，弹层关闭后恢复可见。

3.4 底部安装浮层的展示规则

  • 登录态限制：仅未登录用户展示；用户登录后浮层隐藏，且不再触发。
  • 触发时机：未登录用户每次进入 H5 首页均触发一次，不做已安装判定，不做会话级去重。
  • 让位规则：进入首页时若存在其他弹窗（活动弹窗、公告弹窗等），浮层让位不弹；其他弹窗关闭后不补弹，本次访问不再展示浮层。
  • 关闭方式（不变）：仅点击「取消」按钮可关闭；点击浮层外遮罩区域不关闭；打开后 5 秒无操作自动关闭。
浮层的触发时机由上述规则直接约定，不读取、也不新增「弹框时间点」「弹框间隔时间」配置——这两个字段仍仅归属「引导安装」。

3.5 与「引导安装」的关系

「引导安装」为并列的第三个独立开关，控制引导安装弹窗（安卓 / iOS 安装流程），不受本次拆分影响，其子字段（弹框内容、弹框时间点、弹框间隔时间、弹框安装类型等）维持现状。

拆分前 PRD 中的「特殊情况」条款——下载按钮与引导安装同时开启、弹框时间点为「访问主页」时，未登录用户仅显示下载按钮，登录后引导安装弹框叠加覆盖——拆分后不再需要作为特例规避：底部安装浮层已明确为未登录专属，引导安装弹窗（时间点＝访问主页）在用户登录后触发，两者因登录态天然错开，不存在同屏叠加。顶部横幅与引导安装弹窗可同屏，弹窗遮罩覆盖横幅，横幅不被关闭。

后台开关前台组件登录态触发时机来源
顶部横幅H5 首页顶部下载提示横幅不限页面加载即常驻
底部安装浮层H5 首页底部安装浮层（带遮罩）仅未登录每次进入首页，不读弹框时间点
引导安装引导安装弹窗（安卓 / iOS 分支）按弹框时间点，访问主页时为登录后弹框时间点 + 弹框间隔时间

3.6 点击安装后的交互

顶部横幅与底部安装浮层的安装按钮共用同一套安装交互逻辑，与拆分前完全一致：点击 → 已安装唤起判定 → 未命中则按浏览器环境路由（Chrome / 非 Chrome）→ 进入对应设备的安装机制（安卓 PWA / APK、iOS 保存桌面）。本次不做任何改动。

五、数据与兼容

5.1 存量数据迁移

上线时对所有已存在的渠道配置（含官方渠道、推广渠道、历史批量创建渠道）执行一次性迁移：

原「下载按钮」值迁移后「顶部横幅」迁移后「底部安装浮层」
开启开启开启
关闭关闭关闭
迁移后所有存量渠道的前台表现与上线前完全一致，无需运营介入重配。

5.2 校验规则

两个字段均为必填，保存时各自校验非空；无需校验「至少开启一个」，两者同时关闭为合法配置（等同于原下载按钮关闭）。两字段之间无联动置灰。

5.3 操作日志

渠道新增 / 编辑的操作日志中，原「下载按钮」变更项拆分为「顶部横幅」「底部安装浮层」两条独立记录，分别记录变更前后值。

六、不在本次范围

  • 批量替换功能不新增「更换下载按钮开关」替换类型，维持更换安装包 / 更换安装引导 / 更换跳转域名三类。
  • 推广渠道列表页不新增「顶部横幅」「底部安装浮层」展示列。
  • 底部安装浮层不新增独立的「弹框时间点」「弹框间隔时间」配置字段。
  • 两个前台组件的 UI 样式、中葡文案、图标取值来源均不调整。
  • 「引导安装」开关及其全部子字段不做任何改动。
