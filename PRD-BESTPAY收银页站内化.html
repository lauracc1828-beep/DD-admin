一、需求背景与范围

H5 存款页选择 BESTPAY 并提交后，平台当前的处理方式是打开三方收银台的内嵌页面（WebView），由 PixPay 侧渲染二维码与支付说明。该方式存在三项问题：页面视觉与平台割裂、三方页承载的免责与警示内容不受平台控制、以及会员一旦离开该页即无法再回到同一笔待支付订单。

本次需求将 BESTPAY 的收银环节改为平台站内页面：平台在下单后直接取回三方返回的 PIX 付款码串与过期时间，由平台自行渲染收银页，并补充三方页不具备的订单信息区与失效后的重新发起入口。页面布局与信息层级对标参考平台的站内收银页，展示数据取自 BESTPAY 下单接口的返回内容。

四、三方接口字段依赖

站内渲染收银页的前提是 BESTPAY 下单接口返回以下内容。已确认接口具备返回原始数据的能力，本章作为联调时的字段核对清单。

字段前台用途来源必需性说明
PIX 付款码串
（copia-e-cola）		生成二维码、主按钮复制、脱敏地址行BESTPAY必需以文本串返回，二维码由前台自行编码渲染，不使用三方提供的图片地址，避免图片加载失败导致页面不可用。
expireAt有效时间倒计时、失效判定BESTPAY必需绝对时间点。前台按「expireAt − 当前服务端时间」换算剩余时长，不使用相对秒数，避免网络延迟累计误差。
订单金额金额区平台必需取平台下单金额，并与三方返回金额比对，不一致时按 9.1 处理。

平台订单号订单信息区平台必需收银页展示的订单号为平台充值单号，与充值记录、客服查单口径一致。
下单时间订单信息区「创建时间」平台必需取平台订单创建时间，格式 YYYY-MM-DD HH:mm:ss。
订单状态订单信息区「订单状态」平台必需进入页面时查询一次，不轮询。

六、收银页显示与交互逻辑

6.1 入口、返回与回访

  1. 主入口：存款页选择 BESTPAY、输入有效金额并点击「立即充值」，校验通过且下单成功后跳转至站内收银页（独立页面，非存款页内的浮层）。原「打开三方收银台 WebView」的行为取消。
  2. 提交按钮：点击后进入处理中状态（置灰、文案改为「处理中...」）直至下单接口返回，防止重复下单。
  3. 返回：收银页左上角返回键回到存款页，订单不作废、不取消。
  4. 回访：充值记录中的待支付且未失效订单可点击回到对应收银页继续支付；已失效或已完成的订单点击不进入收银页，轻提示订单已失效或已完成。
  5. 记录入口：收银页与存款页导航栏右侧均提供充值记录入口。
  6. 重复下单：会员返回存款页后再次提交，生成新订单与新付款码，原订单在其 expireAt 之前仍然有效，与说明②「如需再次支付，请返回并重新发起充值」的表述一致。

6.2 支付说明区

页面顶部为三条带项目符号的说明，自上而下依次为扫码指引、单次支付提示、支付后指引。前两条为常规灰度文案，第三条为高亮文案（视觉层级以 UI 设计稿为准）。文案内容见第八章。

6.3 金额与二维码

  1. 金额：居中展示本次充值金额，格式 R$ 1.234,56，为页面视觉重心。右侧带复制图标，复制内容为纯数值（不含货币符号与千分位），便于会员在支付应用内直接粘贴。
  2. 二维码：由 PIX 付款码串编码生成，白底居中展示，四周保留静区以保证扫码识别率。
  3. 付款码串获取失败或为空时，按 9.2 处理，不展示空白二维码。

6.4 复制入口

位置复制内容失效后是否可用
金额右侧图标充值金额纯数值否，轻提示订单已失效
主按钮「复制二维码」完整 PIX 付款码串否，按钮置灰
二维码地址行图标完整 PIX 付款码串否，轻提示订单已失效
订单号右侧图标平台订单号是，失效后仍可复制以便联系客服

所有复制动作成功后统一轻提示「复制成功」。二维码地址行的展示值为脱敏串，复制的始终是完整串，不复制脱敏后的展示文本。

6.5 有效时间与失效处理

  1. 取值口径：倒计时剩余时长 ＝ 三方返回的 expireAt − 当前服务端时间，不使用平台固定时长。
  2. 展示格式：剩余时长不足 1 小时时展示为「{分}m {秒}s」，满 1 小时起展示为「{时}h {分}m {秒}s」，每秒刷新。
  3. 归零处理：倒计时归零即视为订单失效，页面同步变化为——二维码置灰并覆盖失效蒙层（蒙层文案「二维码已失效」）；主按钮「复制二维码」置灰不可点击；有效时间位与订单状态位均改为「已失效」；页面底部出现「重新发起充值」按钮，点击返回存款页（清空金额输入，渠道保持选中 BESTPAY）。
  4. 会员在页面停留期间归零，无需刷新页面即时生效；重新进入页面时若已过期，直接以失效态渲染。

6.6 订单信息区

位于页面底部，以分隔线与上方内容区隔开，三行左标签右取值结构。

字段取值说明
订单状态待支付 / 已失效待支付为高亮态、已失效为警示态，具体色值以 UI 设计稿为准。本期不含「已完成」态的页内切换，见第一章范围说明。
创建时间平台订单创建时间格式 YYYY-MM-DD HH:mm:ss。
订单号平台充值订单号完整展示不截断，过长自动换行；右侧带复制图标。

七、后台配置说明

本期不新增后台配置项。收银页的有效时间取自三方返回值，不开放后台配置；页面各区块为固定展示，不做运营可配。BESTPAY 渠道自身的上下线开关、可见会员层级与单笔限额沿用现有配置，本次不做调整。

是否需要增加一个「收银页展示方式：站内 / 三方 WebView」的渠道级开关作为上线灰度与故障回退手段，见 10.3。

九、边界与异常处理

编号场景处理方式
9.1三方返回金额与平台下单金额不一致不进入收银页，按下单失败处理并轻提示，订单置为异常待人工核查，不向会员展示二维码。
9.2下单成功但付款码串为空或格式非法不进入收银页，轻提示「下单失败，请稍后重试」，停留存款页且输入内容保留。
9.3下单接口超时或报错同 9.2；提交按钮恢复可点击状态。
9.4三方未返回 expireAt视为下单数据不完整，按 9.2 处理。倒计时无可信来源时不进入收银页，避免展示无法判定有效期的二维码。
9.5会员停留期间倒计时归零按 6.5 第 3 条即时切换为失效态，无需刷新页面。
9.6从充值记录点入已过期订单不进入收银页，轻提示订单已失效，引导重新发起充值。
9.7会员在收银页等待期间订单已到账本期不做页内状态轮询，页面仍显示待支付。到账以平台余额与充值记录为准，不影响资金结果。该场景的页面反馈待后续需求评估。
9.8同一会员存在多笔未失效待支付订单各订单互不影响，均可从充值记录分别进入各自的收银页。
9.9复制能力不可用（系统剪贴板权限受限）轻提示复制失败并提示长按手动复制；二维码地址行的展示值仍为脱敏串，不因此改为完整展示。
9.10设备时间与服务端时间偏差倒计时以服务端时间为基准换算初始剩余时长，本地仅做秒级递减，不直接取设备时间与 expireAt 相减。
9.11会员未登录或登录态失效沿用平台现有处理，跳转登录流程。

十、待确认事项

编号事项说明与影响
10.1支付成功后的页面反馈机制本期明确不做订单状态轮询与自动跳转，会员需自行返回查看余额。若后续希望在收银页直接看到到账结果，需补充轮询频率、超时停止策略与成功态的页面表现，建议作为独立需求评估。
10.2三方合规披露内容不迁移的风险三方收银台的免责声明、博彩入金警示框与 PIX / Banco Central 标识本期不搬到站内页。站内化后这些内容将不再向会员展示，需法务或风控确认是否属于必须披露项。若需保留，建议做成默认收起的「支付须知」折叠条，以兼顾页面长度。
10.3是否增加站内 / WebView 切换开关作为上线灰度与三方故障时的回退手段。若需要，需在渠道配置中增加一项展示方式开关，并明确切换的生效范围与时机。
10.4充值记录页的现状与改造量6.1 的回访路径依赖充值记录能区分「待支付 / 已失效 / 已完成」并支持点击跳转。需确认现有充值记录页是否已具备该状态划分与跳转能力，若无则需一并改造。
10.5脱敏规则的确认「前 2 位 + *** + 后 8 位」取自参考平台的展示效果推断。若付款码串格式导致后 8 位无区分度，需调整截取位数。
