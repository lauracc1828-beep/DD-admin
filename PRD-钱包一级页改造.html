一、需求背景与范围

H5 现网的充值与提款是两个彼此独立的二级页面：底部导航第 4 项为「取款」，点击后进入取款页，页面占据整屏并隐藏底部导航，顶部以返回键退出；充值页则没有底部导航入口，只能从首页、我的等页面的按钮进入。由此带来三个问题：其一，充值与提款是同一类资金操作，却分散在两条互不相通的路径上，会员在两者之间切换必须先退出当前页再重新寻找入口；其二，底部导航第 4 项只覆盖提款，入金这一平台更希望引导的动作反而没有常驻入口；其三，进入资金页后底部导航消失，会员失去全局导航，退出路径单一。

本次需求将充值与提款合并为一个「钱包」一级页：底部导航第 4 项由「取款」改为「钱包」并更换图标，点击进入钱包页；钱包页内以顶部 Tab 承载充值与提款两个面板，默认落在充值；页面升为一级页后底部导航常驻、不再提供页内返回键，会员通过底部导航在一级页之间平级切换。充值与提款各自的业务规则、渠道、表单字段与校验逻辑本次均不变更，仅调整其所处的页面层级与进入方式。

二、名词解释

名词说明
一级页底部导航直接指向的页面。特征为底部导航常驻且对应项高亮、页内不提供返回键。本次改造后共五个：首页、优惠、邀请、钱包、我的。
二级页由一级页跳转进入的页面。特征为隐藏底部导航、顶栏左侧提供返回键，返回后回到来源一级页。如充值记录页、提款记录页、收银页、设置提现密码页。
钱包页本次新增的一级页容器，承载充值与提款两个 Tab 面板，不含独立页面标题。
Tab 面板钱包页内与某个 Tab 一一对应的内容区域。同一时刻仅展示一个，切换时页面不重新加载、不改变页面层级。
充值 Tab承载原充值页全部内容的面板，为钱包页默认选中项。
提款 Tab承载原提款页全部内容的面板。
系统返回键安卓物理返回键与系统侧滑返回手势的统称，区别于页面内由平台渲染的返回键。

四、底部导航栏变更

底部导航栏在所有一级页常驻展示，固定于屏幕底部，不随页面内容滚动。共五项，自左至右依次排列，第 3 项为视觉凸起的中置按钮。本次仅变更第 4 项，其余四项的名称、图标、跳转目标与角标逻辑均保持现网不变。

2优惠优惠（不变）不变进入优惠一级页。保留现有未读角标逻辑。

高亮与状态

  • 高亮规则：当前所处一级页对应的导航项为选中态，其余为未选中态。两种状态的视觉差异以 UI 设计稿为准，本文档不描述颜色与样式。
  • 钱包项的高亮范围：会员停留在钱包页期间，无论当前选中充值 Tab 还是提款 Tab，第 4 项始终保持选中态。Tab 切换不影响底部导航的高亮。
  • 二级页：进入任一二级页后底部导航整体隐藏，不以置灰或半透明形式保留。
  • 角标：「钱包」项不承载角标。第 2 项「优惠」与第 5 项「我的」的现有未读角标逻辑不变。

第 4 项改名后，「钱包」承载充值与提款两类操作，与会员在 NEWGPAY 渠道下接触到的「NGC 钱包」（会员在第三方 NewGPay 侧的代币账户，见《NewGPay支付渠道 PRD》第二章）并非同一概念。两者在前台同时出现于提款 Tab 内，需在 UI 文案与视觉上作出区分，避免会员将底部导航的「钱包」理解为第三方代币钱包入口。

五、钱包页结构与显示逻辑

5.1 页面层级与导航

钱包页自上而下由三部分构成：顶部 Tab 栏、内容面板区、底部导航栏。页面不设独立的标题栏——Tab 栏本身即为顶栏，承担页面标识与切换两个职能。

区域是否固定说明
顶部 Tab 栏固定贴屏幕顶部，不随内容滚动。左右居中排布充值、提款两个 Tab，右侧为记录入口。详见 5.2。
内容面板区可滚动展示当前选中 Tab 对应的面板，区域内独立滚动，上下边界分别为 Tab 栏与底部导航栏。
底部导航栏固定贴屏幕底部，不随内容滚动，第 4 项「钱包」保持选中态。详见第四章。

相对现网的层级变更

项目改动前（充值页 / 提款页）改动后（钱包页）
页面层级二级页，各自独立合并为一个一级页，充值与提款降为页内 Tab 面板
底部导航进入后隐藏常驻展示，第 4 项保持选中态
页内返回键顶栏左侧提供，点击退回上一页取消。一级页不提供页内返回键，顶栏左侧不放置任何元素
页面标题充值页「存款」、提款页「取款」取消独立标题，由 Tab 名称承担页面标识
记录入口各自页面顶栏右侧移至 Tab 栏右侧，按当前选中 Tab 指向对应记录页
面板内容渠道、金额、表单、提交按钮等完全沿用，本次不作调整

5.2 顶部 Tab 栏

元素控件类型含义与交互要求
充值 Tab文字 Tab 切换至充值面板。页面默认选中项。选中态与未选中态的文字颜色及选中指示条样式以 UI 设计稿为准。
提款 Tab文字 Tab 切换至提款面板。
Tab 点击热区— 每个 Tab 的可点击区域不小于 44×44 px，在文字可视范围之外向左右扩展透明热区达成；两个 Tab 的热区相邻但不重叠，热区扩展不改变文字之间的视觉间距，也不改变选中指示条的宽度（指示条与文字等宽）。
记录入口图标按钮 位于 Tab 栏右侧。点击进入当前选中 Tab 对应的记录页：充值 Tab 下进入充值记录页，提款 Tab 下进入提款记录页。图标在两个 Tab 下保持一致，不随 Tab 变化。

Tab 切换行为

  • 切换方式：仅支持点击 Tab 切换，不支持内容区左右滑动切换，避免与面板内横向滚动区域（如渠道列表）的手势冲突。
  • 页面状态：切换时页面不重新加载、不改变页面层级、不产生新的返回层级；底部导航保持「钱包」选中态。
  • 滚动位置：切换至某一 Tab 时，该面板的内容区回到顶部。
  • 已填内容：会员停留在钱包页期间，切换 Tab 不清空另一面板已填写的内容；离开钱包页后再次进入，两个面板均重置为初始态。
  • 数据刷新：账户余额等公共数据在进入钱包页时查询一次，两个面板共用同一结果；Tab 切换不触发重复查询。面板内渠道、余额等专有数据的加载时机沿用各自原有逻辑。

5.3 充值 Tab 内容区

面板内容完整沿用现网充值页，包括账户余额、渠道区（BESTPAY / NEWGPAY）、快捷金额、自定义金额输入、限额提示、实际到账金额、提交按钮，以及 NEWGPAY 渠道下的 NGC 钱包卡片与获取说明。各元素的字段定义、取值、校验规则与提示文案详见《NewGPay支付渠道 PRD》第五章与《BESTPAY收银页站内化 PRD》第五、六章。

本次改动仅涉及面板的承载方式，具体为：

  • 原页面顶部的标题栏整体移除，面板内容自 Tab 栏下方直接开始。
  • 原顶栏右侧的充值记录入口移至 Tab 栏右侧，功能与指向不变。
  • 面板底部预留底部导航栏的高度，内容不被底部导航遮挡；提交按钮位于内容流中，随内容区滚动，不作吸底处理。

5.4 提款 Tab 内容区

面板内容完整沿用现网提款页，包括账户余额、提款需投注提示与查看详情入口、渠道区、提款金额与快捷档位、提款方式（CPF / PHONE）、收款信息表单、提交按钮，以及 NEWGPAY 渠道下的 NGC 钱包卡片。各元素的字段定义、取值、校验规则与提示文案详见《增加Phone提款方式 PRD》第五章与《NewGPay支付渠道 PRD》第六章。

本次改动仅涉及面板的承载方式，具体为：

  • 原页面顶部的标题栏整体移除，面板内容自 Tab 栏下方直接开始。
  • 原顶栏右侧的提款记录入口移至 Tab 栏右侧，功能与指向不变。
  • 面板底部预留底部导航栏的高度，内容不被底部导航遮挡；提交按钮位于内容流中，随内容区滚动，不作吸底处理。
  • 提交时的各项前置校验（未完结提款拦截、提现密码未设置引导、提现资料绑定上限等）触发条件与提示形式均不变，仅承载页面由取款页变为钱包页提款 Tab，详见第十一章。

六、入口与跳转映射

平台内所有指向充值或提款的入口，改造后统一进入钱包一级页，并按入口按钮的语义定位到对应 Tab。底部导航「钱包」不含充值或提款的语义指向，固定落在充值 Tab。

首页顶部「充值」按钮充值页钱包页 · 充值 Tab页面层级由二级变一级，底部导航不再隐藏。

我的页「提款」入口取款页钱包页 · 提款 Tab进入后直接定位提款 Tab，不经由充值 Tab 中转。

上表中「其他页面的充值 / 提款按钮」为按页面类型归纳，开发侧需以现网实际存在的全部跳转点为准逐一核对改造，不得遗留仍指向旧独立页面路由的入口。

旧路由兼容

原充值页与取款页的独立路由在本次改造后不再对应实际页面。为保证已投放的站外推广链接、客服消息与历史会话中的深链继续可用，由服务端对旧路由做重定向，规则如下：

请求的旧路由重定向目标说明
原充值页路由钱包页，携带目标 Tab 参数 = 充值重定向对会员无感知，落地后直接停留在充值 Tab。
原取款页路由钱包页，携带目标 Tab 参数 = 提款落地后直接停留在提款 Tab。
  • 重定向在服务端完成，不依赖前端路由兜底，避免会员短暂看到空白页或错误页。
  • 旧路由携带的其他查询参数（如渠道来源、活动标识）原样透传至钱包页，不得在重定向过程中丢失。
  • 重定向长期保留，不设下线时间；新投放链接一律直接使用钱包页路由。

七、二级页与返回逻辑

7.1 页内返回键

  • 钱包页：作为一级页不提供页内返回键，顶栏左侧不放置任何元素。
  • 二级页：充值记录页、提款记录页、收银页、设置提现密码页等维持现状，顶栏左侧提供返回键，点击后回到钱包页并定位到进入该二级页时所处的 Tab。

7.2 系统返回键

当前所处状态按系统返回键的行为
钱包页，无弹窗退回上一个一级页，底部导航高亮同步切换至该页。无上一个一级页时（如启动后直接进入钱包页）退回首页。
钱包页，提款 Tab 选中行为同上，不先切回充值 Tab。Tab 切换不产生返回层级。
钱包页，有弹窗或浮层优先关闭弹窗，停留在钱包页当前 Tab，不退出页面。弹窗关闭后的表单状态按各弹窗所属需求的定义处理。
二级页等同点击页内返回键，回到钱包页并定位到进入前的 Tab。
首页沿用现网逻辑，不在本次改动范围。

7.3 记录页

充值记录页与提款记录页保持为两个独立的二级页，不合并为带 Tab 的单一记录页，页面内容与现网一致。两者的进入方式统一收敛至钱包页 Tab 栏右侧的记录入口，由当前选中 Tab 决定指向。

八、后台配置说明

本次需求不新增、不调整任何后台配置项。底部导航的项目数量、名称、图标、排序与跳转目标，以及钱包页的 Tab 数量、名称、默认选中项与顺序，均为前端固定实现，不提供后台配置入口。

充值与提款面板内部涉及的后台配置——包括支付渠道的启用与排序、金额档位、单笔限额、赠送比例、提款方式的状态与解锁条件、提现资料绑定数量等——全部沿用现有配置项与生效逻辑，配置位置与字段定义不变，详见《NewGPay支付渠道 PRD》第四章与《增加Phone提款方式 PRD》第四章。

十、边界与异常处理

场景处理方式
未登录访问钱包页沿用现网登录拦截逻辑。登录成功后进入钱包页并定位到拦截前的目标 Tab。
软键盘唤起面板内输入框聚焦时，底部导航不得上浮遮挡当前聚焦的输入框。具体采用键盘弹起时隐藏底部导航或压缩内容区的方案，由前端根据终端表现确定，以输入框与其下方的校验提示均完整可见为验收标准。
刘海屏与底部手势条Tab 栏顶部与底部导航栏底部分别预留系统安全区，文字与图标不被遮挡，底部导航的可点击区域不与系统手势条重叠。
公共数据加载失败账户余额等公共数据查询失败时，两个面板均展示失败占位与重试入口，Tab 切换与底部导航不受影响、仍可正常操作。
面板内渠道或方式加载失败沿用《NewGPay支付渠道 PRD》第十章与《增加Phone提款方式 PRD》第九章的既有处理，本次不变。
提款 Tab 有未提交内容时切至充值 Tab不弹确认、不清空，已填内容保留在提款面板；会员切回时内容仍在。离开钱包页后清空。
从二级页返回时来源 Tab 已不可用如提款渠道在会员离开期间被后台关闭，返回后仍落在提款 Tab，由面板内部按既有逻辑展示渠道不可用状态，不自动切换至充值 Tab。
快速连续点击 Tab以最后一次点击结果为准，切换过程中不重复触发数据查询。
钱包页内弹窗与系统返回键弹窗优先消费系统返回键，见 7.2。弹窗存在期间底部导航不可操作。
