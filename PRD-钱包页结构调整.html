一、需求背景与范围

现网底部导航第 4 项为「提款」，点击直达提款表单，存款入口则散落在其他位置。随着存款与取款两侧均新增 NEWGPAY 渠道、PIX 收银环节由三方页面改为站内页面，相关页面数量明显增加，原有的扁平入口已无法容纳这些新页面，也无法表达「存款与取款同属资金操作」的归属关系。

本需求将底部导航第 4 项改造为「钱包」一级页，把存款与取款收敛为页内两个 Tab，并重新划定一级页与二级页的层级与返回规则，为新增页面提供稳定的承载结构。

三、页面层级与流转

3.1 一级页与二级页的划分

层级页面返回键底部导航说明
一级页钱包（存款 Tab / 取款 Tab）无常驻两个 Tab 属同一页面，切换不产生历史记录。
首页 / 优惠 / 邀请 / 我的无常驻本需求不涉及其页面内容。
二级页PIX 收银页有不展示存款选择 BESTPAY 并提交后进入。返回规则见《存款页优化说明（PIX / NewGPay）》。
NewGPay 买币页有不展示App 内嵌的三方页面，平台不参与其页面设计与交互；返回钱包存款 Tab。
存款记录有不展示由存款 Tab 或 PIX 收银页右上角记录入口进入，返回钱包。
取款记录有不展示由取款 Tab 右上角记录入口进入，或提交取款成功后自动跳入；返回钱包。
  1. 二级页统一规则：顶部为标准导航栏（左返回键 + 居中标题），左右两侧图标区等宽以保证标题视觉居中；页面底部不展示底部导航，整屏留给内容。
  2. 滚动位置：每次进入页面时内容区滚动位置重置到顶部；Tab 切换同样重置。

3.2 页面层级流转图

四、钱包一级页顶部结构

  1. Tab 即顶栏：不单设「钱包」页面标题，存款 / 取款两个 Tab 直接作为顶栏内容，与底部导航「钱包」项形成呼应，省去一行标题的垂直空间。
  2. 标签左对齐：两个 Tab 自左起依次排列，不居中。一级页没有返回键，左上角若留空会显得残缺；标签左起正好补上该位置，与右侧的记录入口形成左右配重。
  3. 选中指示：选中项文字为高亮态，下方有与文字等宽的指示条；未选中项为次级灰度。指示条宽度跟随文字，不跟随点击热区。
  4. 点击热区：每个 Tab 的可点击区域高度不小于 46px，宽度在文字基础上左右各外扩内边距，满足 iOS 44pt / Android 48dp 的最小触控尺寸；两个热区相邻但不重叠。
  5. 记录入口：顶栏右侧固定一个记录图标，点击进入当前 Tab 对应的记录页——存款 Tab 进存款记录，取款 Tab 进取款记录。
  6. 默认 Tab：每次从底部导航进入钱包页，默认停留在存款 Tab；会员在页内切换过 Tab 后离开再返回，仍回到存款 Tab，不记忆上次选择。

Tab 的文案由「充值 / 提款」改为「存款 / 取款」，属全局术语统一的一部分，调整范围与对照见《存款页优化说明（PIX / NewGPay）》第三章。

五、底部区域：结算栏与底部导航的共存

存款与取款页的主操作按钮固定在页面底部（见《存款页优化说明（PIX / NewGPay）》第四章），而钱包作为一级页底部已有常驻导航。两者直接叠放会占去约 188px，使表单可视区压缩到不足 500px，首屏放不下完整的金额选择区。

共存规则

状态底部导航结算栏说明
进入钱包页，未输入金额展示展示会员尚未开始操作，导航需可用以便切换去别处。
金额输入框有值收起展示视为会员已进入交易流程，收起导航把空间让给表单，避免误触离开。
清空金额输入框恢复展示展示自动恢复，无需额外操作。
切换 Tab按目标 Tab 的输入状态重新判定切换为目标 Tab 的按钮存款与取款的输入内容相互独立。
提交成功后恢复展示金额归零输入框清空，随之恢复。
二级页不展示按该页自身规则见 3.1。
  1. 收起与恢复带过渡动画，避免页面高度突变造成的内容跳动。
  2. 收起期间底部导航不可点击，会员需清空金额或使用页内返回路径离开。
  3. 该规则仅作用于钱包一级页，其余一级页的导航始终常驻。

六、渠道切换的状态保持

存款与取款的每个 Tab 下均有 BESTPAY 与 NEWGPAY 两个渠道，各自拥有独立的金额输入框。若切换渠道时不处理，新渠道的输入框为空，会同时造成三个问题：结算栏金额跳回零、底部导航因「判定为未输入」而弹回、会员需要重新输入一遍。

保持规则

  1. 金额带过：切换渠道时，已输入的金额平移到目标渠道的输入框。存款两侧为 1 NGC = 1 R$ 的等值关系，取款两侧同为 R$，数值可直接沿用，无需换算。
  2. 快捷档位高亮：带过后按目标渠道自身的档位表重新匹配——金额命中目标档位则高亮该档，未命中则不高亮任何档位。两个渠道的档位表不同，不做跨渠道的档位映射。
  3. 限额校验：始终按当前渠道的限额判定，提示文案也使用当前渠道的币种单位。带过的金额若超出目标渠道限额，在提交时拦截并提示。
  4. 底部导航与结算栏：因金额已带过，两者状态连贯，不出现闪烁。
  5. Tab 之间不带值：存款与取款是方向相反的两笔业务，切换 Tab 时各自保留自己的输入内容，互不影响。

七、终端适配

  1. 安全区：顶栏高度包含顶部安全区（刘海 / 灵动岛），底部导航高度包含底部安全区（Home 指示条），由系统安全区变量注入，不写死数值。
  2. 全屏呈现：在手机视口下页面铺满整屏，不出现外框与留白；内容区高度随视口变化，并规避浏览器地址栏伸缩造成的抖动。
  3. 滚动区域：仅内容区可滚动，顶栏、结算栏与底部导航固定不动；滚动采用惯性滚动并限制滚动链，避免滚到底时带动外层页面。

九、边界与异常处理

编号场景处理方式
9.1在二级页按系统返回手势 / 物理返回键与页内返回键行为一致，不出现「返回到空白页」或直接退出 App。
9.2底部导航收起期间会员尝试点击导航区域该区域已无可点击元素，点击穿透至页面内容，不触发任何跳转。
9.3会员在二级页停留时登录态失效沿用平台现有处理，跳转登录流程；重新登录后回到钱包一级页，不回到原二级页。
9.4取款 Tab 的记录入口在无取款记录时仍可进入，记录页展示空态，不置灰入口。
9.5小屏设备下首屏放不下完整表单内容区正常滚动；顶栏与结算栏固定，保证主按钮始终可见。
9.6横屏或折叠屏展开沿用平台现有适配策略，本需求不单独处理。

十、待确认事项

编号事项说明与影响
10.1原「提款」入口的其他引用点底部导航第 4 项改为「钱包」后，站内其他指向原提款页的入口（活动页、消息、客服话术等）是否需要一并改为指向钱包页取款 Tab，需梳理清单后统一调整。
10.2钱包页是否记忆上次所在 Tab本文定为每次进入均回到存款 Tab。若希望记忆会员上次停留的 Tab，需明确记忆的有效期（本次会话 / 长期）。
10.3底部导航「钱包」的葡语取值暂拟 Carteira，需与现网其余四项的用语风格一并由运营确认。
