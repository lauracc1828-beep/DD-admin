一、概述

背景

目前前端没有统一的弹窗调度：每个弹窗各自判断是否弹出，满足条件即直接显示。登录或注册成功后停留在首页的几秒内，首页公告、强制修改密码、限时充值返利、人工优惠、首充亏损返利可能同时满足条件，用户会连续看到多层叠在一起的弹窗。现有的避让规则只有三条，且注册彩金弹窗拥有关闭其他弹窗的特权。

目标

  1. 任何时刻屏幕上只显示一个弹窗。
  2. 首页自动弹窗按统一的优先级和名额依次展示，避免一次进首页被弹窗连续打断。
  3. 为后续新增弹窗提供接入规范，新弹窗按规范登记即可纳入调度，不再单独约定。

本次需求范围

  • 适用端：巴西 H5 全站（含从桌面图标打开的 PWA）。
  • 新增：统一弹窗调度（不重叠、优先级、首页排队、营销组名额与顺序、弹窗间隔、队列保留）。
  • 调整：底部安装浮层仅对未登录用户展示；注册彩金弹窗取消关闭其他弹窗的特权；网络已断开同时只显示一个；安装引导弹窗只在首页展示。
  • 不变：各弹窗自身的触发条件、频率、文案、样式和关闭方式保持现状（第六章逐个列明）。
  • 本需求不新增前台文案，不涉及后台配置改动。

二、名词定义

名词定义
弹窗带遮罩、需要用户处理后才能继续操作页面的模态弹窗。底部安装浮层虽有遮罩，按 4.7 节单独处理。
一次进首页从进入 H5 首页开始，到离开首页为止。每次从其他页面回到首页都算新的一次进首页；登录完成、强制修改密码完成也视为新的一次进首页。
收集窗口进入首页后等待各弹窗查询结果的时间，最长 2 秒。所有查询提前返回则立即结束。
队列首页待展示的排队类弹窗列表，按优先级和组内顺序排列。
名额一次进首页内某一组最多可展示的弹窗数量。
调度通道弹窗参与调度的方式，共六种：系统异常、门控、用户操作、首页排队、让位浮层、不参与调度。见第三章。

三、弹窗分类与清单

3.1 分类维度

维度取值用途

业务类型系统异常 / 账户安全 / 信息公告 / 营销权益 / 增长引导 / 操作反馈决定优先级和所属组
展示形态模态弹窗 / 浮层 / 横条横条不挡操作，不参与调度
生效范围任意页面 / 首页 / 特定页面只有首页存在排队

3.2 调度通道与优先级

优先级从高到低：系统异常 > 门控弹窗 > 用户操作弹窗 > 首页排队弹窗 > 底部安装浮层。横条不参与调度。

调度通道包含核心规则
系统异常站点配置加载失败、网络已断开、登录已过期随时出现，先关闭当前弹窗再显示自己。见 4.2 节。
门控登录弹窗（自动拉起）、强制修改密码显示期间其他弹窗不进入队列；完成后视为重新进入首页。见 4.3 节。
用户操作用户点击或进入特定页面引起的弹窗立即显示，不排队、不占名额、不限频；显示期间队列暂停。见 4.4 节。
首页排队安装引导弹窗、首页公告、营销组弹窗只在首页，按档位与名额依次展示。见 4.5 节。
让位浮层底部安装浮层有任何其他弹窗显示或排队就放弃。见 4.7 节。
不参与调度顶部横幅、推送授权提示条、添加到主屏幕浮层按各自现有规则展示。见 4.9 节。

四、调度规则

4.1 总原则：同一时刻只显示一个弹窗

  1. 任何时刻屏幕上最多显示一个弹窗，唯一例外是 4.8 节的同一流程后续弹窗。
  2. 高优先级弹窗到达时，按 3.2 节的优先级处理：系统异常抢占当前弹窗；其余通道的弹窗不抢占正在显示的弹窗，按各自规则等待或放弃。
  3. 任意两个弹窗之间间隔 2 秒：上一个弹窗关闭后 2 秒，下一个弹窗才显示。同一流程的后续弹窗、系统异常不受此限。
  4. 横条（顶部横幅、推送授权提示条）不算弹窗，可与弹窗同时存在。

4.2 系统异常

  1. 包括站点配置加载失败、网络已断开、登录已过期，任意页面都可能出现。
  2. 出现时，先关闭当前显示的弹窗，再显示系统异常弹窗：
    • 被关闭的是首页排队弹窗：放回队列，按 4.6 节保留；
    • 被关闭的是用户操作弹窗（如充值成功、进游戏确认）：直接作废，不再弹出；
    • 被关闭的是门控弹窗：不恢复，系统异常确认后按其自身处理继续。
  3. 同一种系统异常同时只显示一个：多个请求同时遇到断网，只显示一个「网络已断开」。
  4. 系统异常显示期间，排队弹窗、用户操作弹窗均不显示。
  5. 各系统异常确认后的处理保持现状：站点配置加载失败、网络已断开确认后刷新页面；登录已过期确认后清空登录状态并拉起登录弹窗（门控）。

4.3 门控弹窗

  1. 包括自动拉起的登录弹窗和强制修改密码弹窗。
  2. 门控弹窗显示期间，自动触发的弹窗不进入队列，用户操作弹窗无法触发；系统异常除外。
  3. 登录完成或修改密码完成后，视为新的一次进首页：各组名额清零，队列清空，各弹窗按自身规则重新判断；首页公告按「登录成功」时机判断。
  4. 未登录用户进入首页时如触发登录弹窗（全站强制登录、推广链接带注册参数），先显示登录弹窗，首页公告等排队弹窗不显示。

4.4 用户操作弹窗

  1. 用户点击或进入特定页面引起的弹窗，立即显示，不进入队列。
  2. 不占用任何组的名额，不设频率限制；各弹窗自身已有的频率规则（如注册彩金「去绑定」的今日不再提醒）保持现状。
  3. 用户操作弹窗显示期间，首页队列暂停，安装引导弹窗同样等待；用户操作弹窗关闭 2 秒后，队列继续。
  4. 注册彩金弹窗不再关闭首页公告和限时充值返利，按普通用户操作弹窗处理。
  5. 进入页面即弹出的弹窗（助力转盘满进度、设置资金密码提醒、活动已关闭）按用户操作弹窗处理。

4.5 首页排队

4.5.1 档位与名额

档位弹窗每次进首页名额规则
第 1 档安装引导弹窗1排他：在队列中时排在最前；显示期间除系统异常外的弹窗都等待，关闭后其他弹窗再显示。频率按后台「弹框间隔」配置，保持现状。
第 2 档首页公告1首页公告为一个弹窗（多条公告在弹窗内轮播）。每条公告的弹出时机和频率按后台配置，保持现状。
第 3 档营销组2组内顺序：每日首登转盘 > 首充亏损返利 > 限时充值返利 > 人工优惠。超出名额的营销弹窗保留到下次回首页。

不设总数上限：一次进首页最多显示 4 个排队弹窗（安装引导 1 + 首页公告 1 + 营销组 2）。

4.5.2 排队流程

  1. 进入首页时开启收集窗口，最长等待 2 秒，收集本次触发的排队弹窗，并取出上次保留的弹窗（4.6 节）。
  2. 收集窗口结束后：去掉重复的弹窗，剔除已失效的弹窗，再按档位和组内顺序排序，依次显示。
  3. 收集窗口结束后才到达的弹窗（包括停留首页期间轮询查到的限时充值返利、首充亏损返利），排在已排好的弹窗之后；同时后到达的多个弹窗之间按档位和组内顺序排列。
  4. 停留首页期间后到达的弹窗同样占用本次进首页的名额；名额已用完的，保留到下次回首页。
  5. 每个弹窗显示前再次检查是否仍然有效；已失效的直接丢弃，不占名额。

4.5.3 回首页时是否再弹

每次回首页都是新的一次进首页，名额重新计算。具体某个弹窗回首页时是否再弹，按该弹窗自身的机制判断，保持现状：

弹窗回首页时的现有机制
安装引导弹窗按后台「弹框时间点」与「弹框间隔」判断。弹框时间点为「用户充值」「首次提现」时，等用户回到首页、且当前没有用户操作弹窗时进入队列。
首页公告按每条公告配置的时机（进站 / 登录成功 / 从其他页面回到首页）和频率（每次回首页 / 每天一次 / 只弹一次 / 每次进站或登录）判断；用户勾选「今日不再提醒」的当天不再弹。
每日首登转盘每天首次登录弹一次，抽奖次数增加时也弹。本需求只确定其调度位置（首页、营销组第一），是否上线另行安排。
首充亏损返利停留首页期间同一笔奖励只弹一次，离开再回首页重新弹，直到用户领取。
限时充值返利停留首页期间定时查询，有可用活动即弹；「今日不再弹出」由后端记录。
人工优惠每次回到首页、在首页登录成功时查询，有待处理的优惠就弹，直到用户处理。

4.6 队列保留

  1. 离开首页时，队列中尚未显示的弹窗（含因名额用完而未显示的营销弹窗）保留，下次回首页时显示。
  2. 下次回首页时，保留的弹窗与新触发的弹窗合并，按档位和组内顺序统一排序；同一个弹窗只显示一次；保留的弹窗同样占用该次进首页的名额。
  3. 保留只在本次打开站点期间有效。刷新页面、关闭后重新打开站点时队列清空，各弹窗按自身规则重新判断。
  4. 登录完成、修改密码完成后队列清空（4.3 节）。
  5. 保留的弹窗在显示前已失效的直接丢弃，例如限时充值返利倒计时已结束。

4.7 底部安装浮层

  1. 展示条件：下载按钮开启时，未登录用户进入首页，且收集窗口结束时没有其他弹窗在显示或排队。已登录用户不展示。
  2. 收集窗口结束时有其他弹窗在显示或排队的，本次进首页直接放弃，不补弹。
  3. 浮层显示期间有排队弹窗、系统异常或门控弹窗到达时，浮层立即关闭，到达的弹窗按规则显示；浮层不补弹。
  4. 不占用任何组的名额。5 秒自动关闭、点击「取消」关闭等其他规则保持现状，详见《安装引导模块 PRD》3.3 节。

4.8 同一流程的后续弹窗

  1. 用户在弹窗内点击按钮后打开的下一步弹窗，与原弹窗属于同一流程，可以叠在原弹窗之上或替换原弹窗，不算重叠。
  2. 后续弹窗不进入队列、不占名额、不受 2 秒间隔限制；叠加或替换的方式保持各弹窗现状。
  3. 当前包括：
    • Google 浏览器引导遮罩：在顶部横幅、底部安装浮层、安装引导弹窗中点击「安装」后判断浏览器时弹出，可叠在安装引导弹窗之上；
    • 首充亏损返利：领取成功后的加倍引导；
    • 人工优惠：领取后的领取成功提示。

4.9 不参与调度的组件

组件说明
顶部横幅首页顶部横条，不挡操作，可与弹窗同时存在，规则保持现状。
推送授权提示条PWA 打开且通知权限未选择时显示在页面顶部，无遮罩，不挡操作，规则保持现状。
添加到主屏幕浮层只在仿应用商店页弹出，不在 H5 首页，不涉及首页调度，规则保持现状。

安装引导弹窗首页排队 · 第 1 档调整只在首页显示（现状为任意页面）；进入队列排在最前，显示期间其他弹窗等待；有用户操作弹窗时等待其关闭。
保持弹框时间点、弹框间隔；间隔配置为 0 时无关闭按钮（强制引导下载）。
首页公告首页排队 · 第 2 档调整不再被注册彩金弹窗收起；与限时充值返利等不再同时显示。
保持每条公告的时机、频率、排序、今日不再提醒、图片加载成功才弹。
每日首登转盘首页排队 · 营销组第 1调整确定调度位置。
保持是否上线另行安排，上线时按此位置接入。
首充亏损返利首页排队 · 营销组第 2调整进入队列，占营销组名额。
保持查询频率；领取后的加倍引导；未领取前持续弹出。
限时充值返利首页排队 · 营销组第 3调整进入队列，占营销组名额；不再被注册彩金关闭；排队期间倒计时结束则丢弃。
保持查询频率、倒计时到 0 自动关闭、今日不再弹出。
人工优惠首页排队 · 营销组第 4调整进入队列，占营销组名额；有多条待处理优惠时，每条算一个弹窗，各占 1 个营销组名额，多条之间按现有顺序排列，超出名额的保留到下次回首页。
保持无关闭按钮；未处理前持续弹出。
底部安装浮层让位浮层调整只对未登录用户展示；有任何其他弹窗显示或排队即放弃。
保持5 秒自动关闭、点「取消」关闭、遮罩。
注册彩金弹窗用户操作调整取消关闭首页公告和限时充值返利的特权。
保持进游戏检查顺序、去绑定的今日不再提醒。
其他进游戏确认用户操作保持按顺序检查，彼此不重叠。
离开游戏提示用户操作保持确认后离开；回到首页后首页排队开始。
充值成功用户操作保持3 秒后自动回首页；回首页后首页排队开始。
神秘矿场挖矿结果、助力转盘满进度、设置资金密码提醒、活动已关闭、操作反馈类用户操作保持各自触发条件和频率。
顶部横幅、推送授权提示条、添加到主屏幕浮层不参与调度保持现有规则。

七、边界与异常

场景处理
注册或登录成功后停在首页，公告、限时充值返利、人工优惠、首充亏损返利同时满足条件若需强制修改密码，先显示强制修改密码；完成后按新的一次进首页排队：公告 → 首充亏损返利 → 限时充值返利，人工优惠因营销名额已满保留到下次回首页。
安装引导弹框间隔配置为 0安装引导弹窗无关闭按钮，其后的排队弹窗一直等待，为强制引导下载的预期效果。
安装引导弹窗显示中，用户点击「安装」浏览器判断不通过时，Google 浏览器引导遮罩叠在安装引导弹窗之上（4.8 节）。
限时充值返利在队列中等待时倒计时结束丢弃，不显示，不占名额。
排队弹窗显示中遇到网络已断开排队弹窗关闭并放回队列，显示网络已断开；确认后刷新页面，队列清空，各弹窗重新判断。
充值成功弹窗显示中遇到登录已过期充值成功弹窗作废；显示登录已过期，确认后拉起登录弹窗。
有 3 条待处理的人工优惠，且没有其他营销弹窗每条算一个弹窗：本次进首页显示前 2 条，第 3 条保留到下次回首页。
停留首页时轮询查到首充亏损返利，营销名额已用完不显示，保留到下次回首页。
离开首页时还有未显示的弹窗保留；下次回首页与新触发的弹窗合并排序，同一弹窗只显示一次。
刷新页面或关闭后重新打开站点保留的弹窗清空，各弹窗按自身规则重新判断。
未登录用户进首页，有公告要弹显示公告；底部安装浮层本次放弃。
未登录用户进首页，没有其他弹窗下载按钮开启时显示底部安装浮层；浮层显示期间有弹窗到达则浮层关闭。
全站强制登录站点，未登录用户进首页先显示登录弹窗（门控），公告等排队弹窗不显示；登录完成后按新的一次进首页排队。
