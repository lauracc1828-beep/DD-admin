一、需求背景与范围

VIP管理（《【站点】vip管理（对齐熊猫）》）上线后，对照熊猫的规则发现几处发放、领取和后台展示上的差异。经讨论，本需求只处理以下两个优化点，其余 VIP 规则保持现状。

本次改动范围

序号优化点涉及端改动内容章节
1受众用户1 · 晋级奖励服务端、客户端领取规则为「受众用户1」时，领取晋级奖励也要满足受众条件，不满足的弹充值引导。第三章
2作废奖励的后台显示服务端、后台「等级奖励记录」增加「已作废」状态和筛选项，备注列写明作废原因；保级关闭降级时保留未领取的晋级奖励记录并标为已作废；上线时刷新存量记录。第四章

不在本需求范围：日/周/月奖励所需流水为 0 时的派发规则，见《【站点】VIP奖励机制优化》；奖励生成规则、奖励金额、稽核倍数与限定平台、保级规则（除 4.1 中降级时晋级奖励记录的保留方式外）、周期中途晋级的处理、作废时间点、「回收作废」与「受众用户2」的领取规则、前台各页签与弹窗样式，均沿用现有 VIP管理 PRD 与当前实现，本需求不做改动。

二、改动前后对比

项改动前改动后
受众用户1 · 领取晋级奖励不校验受众条件，直接可领。要满足受众条件；不满足的弹充值引导弹窗，充值后才能领。
受众用户1 · 「一键领取」「领取全部晋级奖励」晋级奖励部分不校验受众条件。与日/周/月奖一样校验受众条件。

「等级奖励记录」状态筛选未领取 / 已领取未领取 / 已领取 / 已作废
保级关闭时降级，未领取的晋级奖励作废，记录不保留。作废，记录保留，状态「已作废」，备注「降级作废」。会员仍不能领取，再次升级时仍按原规则重新生成。

三、优化点 1：受众用户1 下领取晋级奖励校验受众条件

规则

  • 适用条件：后台「领取规则」选择「受众用户1」（跨天/跨周/跨月未领取奖励回收作废，N 天内充值）。
  • 受众条件：与日/周/月奖相同，即近 N 天（不含当天）或当天有任意金额的成功充值。N 取后台「N天内充值」的配置值。
    • 任意金额：有一笔成功到账的充值即达标，不设最低金额，0.01 也算。不按 VIP 等级区分充值门槛。
    • 统计区间：往前 N 个自然日加上当天，共 N+1 天。例如 N=7、今天为 11-10，11-03 00:00 至当前时刻之间有成功充值即达标。
    • 时区与切天：沿用现有 VIP 规则，站点时区 UTC-3，00:00 切天。
  • 只加充值校验：本优化只新增充值受众校验。领取晋级奖励时不新增、不改动流水校验（晋级由晋级需充值 / 需流水触发，领取时不再校验流水）。
  • 校验时机：会员点击领取时由服务端校验，前台不提前置灰。充值不达标时，晋级领取按钮和「Coletar Tudo」都保持可点，点击后才弹充值引导；按钮仅在没有可领奖励时置灰（现有规则）。
  • 满足条件：一次发放所有未领取的晋级奖励，全部到账，弹领取成功弹窗，展示合计到账金额。
  • 不满足条件：不发放，弹充值引导弹窗。文案「Receba uma recompensa exclusiva após efetuar qualquer depósito」（完成任意金额充值后，即可获得专属奖励），按钮「Depósito」跳转充值页、「Cancelar」关闭弹窗。晋级奖励保留为未领取，充值成功后可再领。
  • 晋级奖励不作废：晋级奖励没有周期，不因跨天/跨周/跨月作废；本优化只增加领取校验，不改变晋级奖励的累加和保级相关的作废规则。

涉及的领取入口

入口受众用户1 下的处理
「Bônus」页签底部「Reclamar Recompensa de Upgrade」只领晋级奖励，不领日/周/月奖。按上述规则校验：满足则一次领取全部未领取的晋级奖励；不满足则弹充值引导弹窗，一笔都不发。
顶部「Coletar Tudo」（一键领取）领取全部可领奖励（未领取的晋级奖励 + 流水已达标的日/周/月奖）。满足则一并领取；不满足则弹充值引导弹窗，一笔都不发。

受众用户1 下，晋级奖励与日/周/月奖校验的是同一个充值条件，结果只有「全部满足」或「全部不满足」，不会出现日/周/月达标而晋级不达标的情况。因此以下情况统一处理为不发放任何奖励，只弹充值引导：只有晋级奖励待领且充值不达标；晋级与日/周/月奖都待领且充值不达标。

领取规则为「回收作废」「受众用户2」时，晋级奖励领取不校验受众条件，保持现状。

四、优化点 2：等级奖励记录增加「已作废」状态

页面路径：福利中心 ＞ VIP管理 ＞ 等级奖励记录。

4.1 状态定义

状态含义
未领取已生成、尚未领取，且还没到作废时间，会员仍可领取。
已领取会员已领取，或「受众用户2」到期时系统自动发放。
已作废系统已作废，会员不能再领取。作废后状态不再变化。
  • 展示名统一为「已作废」：筛选项、列表、导出均显示「已作废」，不使用「过期」等其他叫法。数据库中已有「过期」状态值的，可沿用该值，只统一展示文案。
  • 仍在有效期内、可领取的「未领取」记录不作废。

变为「已作废」的场景与备注

场景作废时刻备注列写入
日/周/月奖到期未领取（领取规则为回收作废、受众用户1），即现有「过期」状态的数据到达该奖励的作废时间点（沿用现有规则）过期作废
领取规则为受众用户2，到期时不满足受众条件、系统未自动发放到达该奖励的作废时间点过期作废
晋级奖励未领取，保级关闭时会员降级降级时降级作废

只有以上场景会变为「已作废」。

保级关闭时降级的晋级奖励记录

原规则为保级关闭时降级，未领取的晋级奖励作废且记录不保留。本需求改为保留该记录：状态改为「已作废」，备注「降级作废」，会员不能再领取。其余保级规则不变：再次升级时按原规则重新生成新的晋级奖励记录，可再次领取。

备注规则

  • 作废原因只在后台「等级奖励记录」列表和导出中展示；会员端（H5 / App）不展示作废原因，只是该奖励不再显示为可领取。
  • 备注列原本已有内容的，作废原因追加在原内容后，用「；」分隔，例如「原内容；过期作废」。

4.2 列表与筛选

位置改动
筛选区「状态」下拉单选，选项改为：全部（默认）/ 未领取 / 已领取 / 已作废。
列表「状态」列按 4.1 展示三种状态；「已作废」用灰色文字展示。
列表「领取时间」列状态为「已作废」时展示「-」，导出同样为「-」。
列表「备注」列状态为「已作废」时展示作废原因（过期作废 / 降级作废）。
「导出」导出文件的状态、备注与列表一致，按当前筛选条件导出。

列表其余列（手机号、订单号、福利金额、福利类型、稽核倍数、订单生成时间、账号类型、会员等级、上级代理）和其余筛选项不变。

4.3 上线时的存量数据处理

  • 上线时，把现有「过期」状态的记录，以及已被系统作废、列表中仍显示「未领取」的历史记录，统一改为「已作废」。
  • 备注：能区分作废原因的，分别写入「过期作废」或「降级作废」；区分不了的，写「过期作废」。现有「过期」状态的记录写「过期作废」。
  • 上线前已按原规则删除的降级晋级奖励记录不补建。
  • 仍在有效期内的「未领取」记录、所有「已领取」记录不变。
  • 存量处理只改展示状态，不改变奖励金额，也不影响会员的领取结果。

五、边界与异常处理

场景处理方式
受众用户1 下，会员在充值引导弹窗点「Depósito」但没有完成充值回到 VIP 页面后晋级奖励仍为未领取，再次点击仍弹充值引导弹窗。
受众用户1 下，会员当天充值成功后立即领取当天有充值即满足受众条件，可正常领取。
运营把领取规则从受众用户1 改为其他规则改动保存后，会员再领取晋级奖励时按新规则处理，不再校验受众条件。
前台未刷新、会员点击已作废的奖励服务端拒绝发放，前台提示领取失败并刷新奖励列表。
同一会员并发点击领取服务端按奖励记录加锁，同一记录只发放一次；作废与领取同时发生时，先完成的生效。

六、验收标准

  • 领取规则为受众用户1、会员不满足 N 天内充值时，点击「Reclamar Recompensa de Upgrade」弹充值引导弹窗，晋级奖励不发放。
  • 同一场景下点击「Coletar Tudo」弹充值引导弹窗，晋级奖励和日/周/月奖都不发放。
  • 满足受众条件（含当天充值，0.01 也算）后，以上两个入口都能正常领取，弹领取成功弹窗并展示合计到账金额。
  • N=7 时，8 天前（第 N+1 天之前）的充值不算达标，7 个自然日前至今的充值算达标。
  • 「Reclamar Recompensa de Upgrade」只领取晋级奖励，不领取日/周/月奖。
  • 充值不达标时，晋级领取按钮和「Coletar Tudo」不置灰，点击后弹充值引导。
  • 领取规则为回收作废、受众用户2 时，晋级奖励领取不校验受众条件。
  • 直接调用领取接口时，服务端同样按受众条件校验。
  • 日/周/月奖过期后，「等级奖励记录」中状态为「已作废」，备注「过期作废」，领取时间「-」。
  • 保级关闭、会员降级后，未领取的晋级奖励记录保留，状态为「已作废」，备注「降级作废」；再次升级时重新生成新的晋级奖励记录。
  • 受众用户2 到期未自动发放的记录为「已作废」，备注「过期作废」。
  • 会员端不展示作废原因；备注原有内容时按「原内容；过期作废」拼接。
  • 状态筛选包含「已作废」，筛选和导出结果正确。
  • 上线后，历史上已作废的记录显示为「已作废」，有效期内的未领取记录不受影响。
