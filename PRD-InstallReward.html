一、需求概述

推广渠道的渠道设置（安卓 / 苹果）和安装引导模块中都已有「安装pwa/App赠送」配置，但目前只能保存、不会发放。本需求让该配置正式生效：会员在 PWA 或 APP 内登录后，系统按配置自动向会员发放安装奖励，并补齐账变与统计。

本次范围

序号改动项涉及端说明章节
1配置生效后台、服务端去掉「可保存但暂不上线生效」的限制；补充「赠送金额」「打码倍数」的输入规则。第三章
2发放逻辑服务端判定时机、判定次数、按注册渠道读取配置、发放条件、自动到账与稽核。第四章
3账变与统计服务端、后台、前台账变记录新增二类账变「安装pwa/App赠送」；发放记录进入优惠统计；金额计入注册渠道的推广效果报表「赠送金额」。第五章

不在本次范围：

① 前台展示不改动。顶部横幅、底部安装浮层、引导安装弹窗的内容与触发规则保持现状；弹窗中的「显示赠送金额」仍只作展示，读取会员当前访问渠道的配置，与实际发放金额相互独立。

② 不做已安装判定，引导安装弹窗按弹框时间点 / 间隔持续弹出的规则不变。

③ 发放后不新增任何前台提示或弹窗；安装奖励不进入待领取页面。

项改动前改动后

三、后台配置

3.1 配置位置

菜单位置配置套数适用会员
推广渠道管理 → 推广渠道管理新增渠道 / 编辑渠道 / 批量新增渠道弹窗 → 渠道设置「安卓」Tab、「苹果」Tab每个渠道安卓、苹果各一套，相互独立注册渠道为该渠道的会员
推广渠道管理 → 推广渠道管理批量替换 → 更换安装引导 → 「安装送彩金」按所选「渠道安装类型」只修改对应平台（安卓 / 苹果）的配置，规则沿用现状同上
推广渠道管理 → 安装引导配置页「安装pwa/App赠送」每个商户一套，安卓、iOS 共用无注册渠道的会员（官方渠道）

3.2 字段说明

以下三个字段在上述所有位置的规则一致。

字段必填控件含义输入要求与校验
安装pwa/App赠送 必填 下拉单选 会员在 PWA / APP 内登录后，是否发放安装奖励及发放条件。 可选：关闭 / 充值用户赠送 / 无需充值赠送；默认「关闭」。
「关闭」：不发放。
「充值用户赠送」：判定时已有成功到账充值记录的会员才发放。
「无需充值赠送」：不要求充值记录，满足判定条件即发放。
选「关闭」时下方两个字段收起，已填写的值保留，再次选非「关闭」时回显。
↳ 赠送金额 条件必填 数字输入 每个会员实际到账的奖励金额（BRL），按固定值发放。与引导安装弹窗的「显示赠送金额」相互独立，两者可以不同。 「安装pwa/App赠送」选非「关闭」时展示且必填。
须大于 0，最多两位小数，不设上限；输入框只能输入数字和一个小数点，超过两位的小数无法输入。
校验：为空时保存，提示「请输入赠送金额」；为 0 时保存，提示「赠送金额须大于0」。
↳ 打码倍数 条件必填 数字输入 奖励到账后需要完成的有效投注倍数，决定该笔奖励的提现稽核要求（见 4.5）。 「安装pwa/App赠送」选非「关闭」时展示且必填。
只能填写 0 或正整数，不设上限；小数点、负号等字符无法输入，失焦时去掉前导 0（如 05 → 5）。0 表示该笔奖励不追加稽核要求。
校验：为空时保存，提示「请输入打码倍数」。

生效时机：配置保存后立即生效。会员按判定时刻读取到的配置处理；已判定过的会员不受之后配置修改的影响。

四、发放规则

4.1 判定时机

会员以 PWA 或 APP 方式打开站点，并且处于登录状态时，服务端进行一次发放判定。以下两种情况都算：

  • 在 PWA / APP 内完成登录；
  • 打开 PWA / APP 时已经是登录状态（如安卓 PWA 与浏览器共用登录态）。
访问方式是否判定
PWA：从手机主屏幕图标以独立窗口打开（安卓 PWA、iOS「保存桌面」）判定
APP：安卓 APK 客户端判定
在手机浏览器内访问 H5不判定
非安卓、非 iOS 设备（如电脑端）以 PWA 方式打开不判定，也不计入判定次数
PWA / APP 内未登录不判定；会员登录后再判定

4.2 判定次数

  • 每个会员账号只判定一次：上线后会员第一次满足 4.1 时判定，无论结果是发放还是不发放，该账号的判定都已结束。之后再次打开 PWA / APP、重新登录、补充值，均不再判定、不补发。
  • 判定时注册渠道的配置为「关闭」，也算已判定，之后配置改为开启也不补发。
  • 同一账号在安卓与 iOS、PWA 与 APP、多台设备上登录，合计只判定一次，以最先满足 4.1 的那次为准。
  • 不限老会员：上线前注册、上线前已安装或已在 PWA / APP 内登录过的会员，上线后第一次满足 4.1 时同样判定。

4.3 配置来源

发放按会员的注册渠道读取配置，与会员这次从哪个链接安装 PWA / APP 无关。

会员注册渠道读取的配置
推广渠道该渠道渠道设置中，与当前登录设备系统对应的一端：安卓设备读「安卓」Tab，iOS 设备读「苹果」Tab。
无渠道（官方渠道）安装引导模块的「安装pwa/App赠送」配置，安卓与 iOS 共用。

引导安装弹窗中的「显示赠送金额」读取的是会员当前访问渠道的配置（保持现状）。会员从其他渠道链接访问时，弹窗显示的金额可能与按注册渠道实际发放的金额不同，以实际发放为准。

4.4 发放条件

配置值判定结果
关闭不发放，判定结束。
充值用户赠送判定时刻该会员已有至少一笔成功到账的充值记录（任意金额）→ 发放；否则不发放，判定结束，之后充值也不补发。
成功充值的统计口径与报表充值金额一致，处理中、失败、取消的订单不算。
无需充值赠送发放。

4.5 到账与稽核

  • 到账方式：自动到账至会员可用余额，无需领取，不进入待领取页面。
  • 金额：按判定时刻配置的「赠送金额」发放固定值。
  • 前台提示：不弹窗、不提示；会员可在前台账变记录中查看（见 5.1）。
  • 稽核：到账时为该会员追加提现稽核要求，所需有效投注 = 赠送金额 × 打码倍数。打码倍数为 0 时不追加。稽核的计算与扣减沿用平台现有活动奖励的规则。

五、账变与统计

5.1 账变类型

层级名称方向说明
一类账变活动优惠加款沿用现有，不新增、不改名。
二类账变安装pwa/App赠送（新增）加款只承载安装奖励的入账记录，不与其他「活动优惠」下的二类账变混记。操作人记为 system。

生效位置：新增后同步出现在后台会员管理「账变记录」的账变二类筛选项与列表、报表查询的账变类型筛选项，以及前台会员账变记录（Relatórios → Detalhes da Conta），前台展示名见第七章。其余列的口径与现有二类账变一致。

5.2 优惠统计

每次发放在福利中心「优惠统计」中生成一条记录：

列取值
活动名称「安装pwa/App赠送（充值用户赠送）」或「安装pwa/App赠送（无需充值赠送）」，括号内为判定时的配置类型。
活动类型其他优惠；活动类型筛选下拉同步增加「其他优惠」选项。
活动 ID无，展示「-」。
领取方式自动领取
奖励类型金额
奖励金额本次发放的赠送金额。
注册渠道会员的注册渠道；无渠道展示「官方渠道」。

其余列（奖励 ID、会员 ID、会员层级、裂变来源、领取时间等）与现有记录口径一致；顶部「活动领取人数」「已领取金额」合计同步计入。

5.3 推广效果报表

  • 安装奖励金额计入会员注册渠道的「赠送金额」字段，与该会员的注册、充值等数据归属同一渠道；不计入会员安装时访问的渠道。
  • 直推 / 裂变的归属按会员本身的归属计入对应数据块，综合效果为两者合计。
  • 「赠送金额」口径保持「统计所有活动奖励总额」，本需求只是把安装奖励纳入其中；报表每 10 分钟更新一次，规则不变。

八、边界与异常

场景处理方式
会员从 B 渠道链接安装，注册渠道是 A按 A 渠道当前设备端的配置判定和发放，金额计入 A 渠道统计。B 渠道弹窗显示的金额只作展示。
「充值用户赠送」下，判定时没有充值，之后才充值判定时已结束，不补发。
判定时配置为「关闭」，之后改为开启该账号已判定，不补发；尚未判定的会员按新配置处理。
判定后运营修改赠送金额或打码倍数已发放的奖励金额与稽核不变；之后判定的会员按新配置。
同一账号先在安卓、后在 iOS 登录 PWA / APP只按最先满足判定条件的那一端判定一次。
同一账号同时打开多个 PWA / APP 窗口服务端按会员账号加锁，只判定一次、只发放一次。
会员一直只在手机浏览器内访问 H5不判定，不发放。
电脑端以 PWA 方式打开站点不判定，不计入判定次数；之后在安卓或 iOS 的 PWA / APP 内登录时正常判定。
上线前已安装 PWA / APP 的老会员上线后第一次以 PWA / APP 方式处于登录状态时判定。
PWA / APP 内未登录，之后才登录登录成功后判定。
