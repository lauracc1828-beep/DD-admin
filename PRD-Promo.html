一、模块概述

推广渠道管理模块用于管理平台所有对外推广渠道的配置，包含渠道创建与编辑、推广商管理、推广效果查看和第三方广告平台埋点回传等功能。商户可在此模块为每条推广渠道生成唯一的带参落地链接，配置落地页类型和埋点回传方式，并通过推广效果报表实时查看各渠道的转化数据。安装引导配置作为独立模块，详见《安装引导模块 PRD》。

关键概念说明

概念说明
渠道ID（ch参数）系统为每条渠道分配的唯一数字标识，附加在渠道链接URL参数中，用于所有后续用户行为的数据归因。APK包本身不内嵌渠道ID，渠道信息通过下载URL参数在安装时透传
跳转域名推广链接的入口域名，负责接收用户点击请求并根据落地指向转发。来源于系统管理-域名管理中已配置并生效的推广域名
落地指向决定用户最终看到的页面类型，共5个选项，本质上分为「下载页类」和「H5页类」两大类，详见子页面一字段说明
埋点回传分两类：① 三方API回传（Facebook API / TK API / Kwai API），均为服务器端回传，不依赖浏览器，数据准确性高，回传参数（Pixel ID / Token）由投流方提供；② 上架包埋点（APK上架包 / IOS上架包），由上架包客户端按统一事件规范上报用户行为，用于上架包渠道的归因与效果分析
直推 vs 裂变直推：用户自己点击推广链接进入；裂变：已注册用户邀请带来的新用户。两者数据在推广效果报表中分开统计
充提差充值金额 - 提现金额，是衡量渠道质量的核心指标。正值表示渠道用户为平台贡献利润，负值表示亏损

埋点类型说明

当前平台支持7种埋点类型：常规推广（无三方回传）+ Facebook API / TK API / Kwai API（三方服务器端API回传）+ APK上架包 / IOS上架包 / APK（上架包埋点）。三方埋点的Pixel ID和Token均由投流方提供。
埋点类型展开字段说明
常规推广无不接入任何第三方广告平台，数据仅在我方后台统计
Facebook API（Facebook服务器接口回传）Pixel ID 必填、Token 必填、test_event_code事件测试 非必填服务器端回传至Facebook广告平台；test_event_code仅供测试使用，测试完成后应删除填入的内容；具体回传事件以Facebook官方文档为准
TK API（TikTok服务器接口回传）Pixel ID 必填、Token 必填、test_event_code事件测试 非必填服务器端回传至TikTok广告平台；test_event_code仅供测试使用，测试完成后应删除填入的内容；具体回传事件以TikTok官方文档为准
Kwai API（快手服务器接口回传）Pixel ID 必填、Token 必填、test_event_code事件测试 非必填服务器端回传至快手广告平台；test_event_code仅供测试使用，测试完成后应删除填入的内容；具体回传事件以快手官方文档为准
APK上架包全渠道回传kwai ID 非必填商户自行封装并上架谷歌商店的马甲包，渠道链接打包进该上架包、由安卓用户在App内访问。「全渠道回传kwai ID」为该渠道在快手侧的全渠道回传标识，由投流方提供，留空表示不做快手全渠道回传；该类型的客户端上报事件清单见 3.5.7 事件说明弹窗，完整需求见《推广渠道埋点类型新增 PRD》
IOS上架包无商户自行封装并上架苹果商店的安装包，渠道链接打包进该上架包、由iOS用户在App内访问；该类型的客户端上报事件清单见 3.5.7 事件说明弹窗，完整需求见《推广渠道埋点类型新增 PRD》
APK无平台自有的H5套壳包，打包指定URL生成安装包、由商户自行分发（不经应用商店），由安卓用户在App内访问；不接入三方回传，也无客户端上报事件清单，数据仅在我方后台统计，列表操作列不展示「事件说明」图标；完整需求见《推广渠道埋点类型新增 PRD》

事件说明弹窗格式：标题为「[埋点类型名称]」，内容为该类型的回传事件列表，每条格式为「中文事件名称 - 事件标识符」。三方API类型的具体内容以三方平台官方文档为准；上架包类型（APK上架包 / IOS上架包）的事件清单见 3.5.7。

与底部安装浮层的关系：底部安装浮层为未登录专属，引导安装弹框在弹框时间点为「访问主页」时于用户登录后触发，两者因登录态天然错开，不存在同屏叠加。顶部横幅与引导安装弹框可同屏，弹框遮罩覆盖横幅，横幅不被关闭。弹框时间点为「用户充值」或「首次提现」时各自独立触发。
↳ 弹框内容条件必填下拉单选引导安装开启后展示；默认「常规升级」「常规升级」：弹窗展示为普通的下载升级提示，不含赠送信息。「赠送彩金升级」：弹窗中额外展示赠送彩金的金额，以吸引用户点击安装。注意：此处展示的金额仅为前端吸引用户的展示值，不等于实际赠送金额（实际赠送金额在「安装pwa/App赠送」中配置）。
↳↳ 赠送金额类型条件必填下拉单选弹框内容选「赠送彩金升级」后展示；可选：固定金额 / 随机金额；默认「固定金额」「固定金额」：弹窗展示一个固定的赠送数值，如「安装送100」。「随机金额」：弹窗展示一个区间值，如「安装送50~200」。两者都只用于弹窗展示；实际赠送金额为「安装pwa/App赠送 → 赠送金额」配置的固定值，不在区间内随机。
↳↳ 显示赠送金额条件必填数字输入固定金额为单一输入框，随机金额为两个输入框（最小值/最大值）仅为弹窗中展示给用户看的营销数字，不影响实际赠送金额。
↳ 弹框时间点条件必填下拉单选引导安装开启后展示；默认「用户充值」「访问主页」：用户每次访问H5首页时触发弹窗（受弹框间隔时间控制）。「用户充值」：用户每次充值回调成功后触发（若用户当前在游戏中则不弹，退出游戏后仍会弹出）。「首次提现」：用户第一次提现回调成功后触发，仅触发一次。
↳ 弹框间隔时间条件必填下拉单选引导安装开启后展示；默认「0小时(强制安装)」；可选：0小时(强制安装) / 1~24小时「0小时(强制安装)」：弹窗强制弹出，无「×」按钮，用户无法关闭，也无法点击弹窗外区域关闭。用户触发下载或完成安装后，弹窗仍保留、不会自动关闭，直至页面刷新或跳转。1~24小时：弹窗弹出后用户可点击弹窗外区域关闭。用户触发下载或完成安装后，弹窗同样保留、不自动关闭；每隔对应时长会再次弹出（不做已安装判定，按间隔持续弹出）。（弹窗关闭逻辑与《安装引导模块 PRD》3.4 节「弹窗关闭逻辑」口径一致）
↳ 弹框安装类型条件必填下拉单选引导安装开启后展示；可选：pwa(快速安装) / apk(需要自己封装) / pwa(优先)+apk(推荐使用)；默认「pwa(快速安装)」（二期：APK 选项已启用，默认值由 apk 调整为 pwa，与《安装引导模块 PRD》2.3 对齐）「pwa(快速安装)」：引导用户将H5页面添加到手机桌面（PWA），若用户使用非谷歌浏览器，点击安装时唤起 Chrome（支持唤起→手机自带跳转确认后转 Chrome 完成安装；不支持唤起→就地按原安装流程处理），详见《安装引导模块 PRD》3.4。「apk(需要自己封装)」：弹窗引导用户下载并安装APK包，需要商户提前上传封装好的APK。「pwa(优先)+apk(推荐使用)」：优先引导安装PWA，若当前浏览器不支持PWA，则降级引导安装APK。
↳↳ APK包地址条件必填文本输入弹框安装类型含APK时展示APK文件的下载地址，用户点击安装时从该地址下载APK包。
↳↳ APK包名—自动填充含APK时展示；选择马甲包后自动读取，手动修改APK包地址后自动清空APK的唯一包标识符，仅作渠道包的标识与管理记录，不用于判断用户设备是否已安装（前台不做已安装判定）。
↳↳ 选择APK条件必填按钮组「选择马甲包」从系统管理-马甲包管理中选（自动填入地址和包名）；「上传」直接上传apk文件（限100MB）。二期：马甲包管理暂未上线，「选择马甲包」下拉暂空，当前用「上传」手动上传跑通。马甲包是经过伪装的APK，外观与普通APP相似，用于规避应用商店审核。选择马甲包后APK包地址和包名自动填入。
安装pwa/App赠送必填下拉单选可选：关闭 / 充值用户赠送 / 无需充值赠送；默认「关闭」；保存后立即生效。选「关闭」时下方两个字段收起，已填写的值保留。适用于注册渠道为本渠道、在安卓设备上以 PWA / APP 方式打开站点并处于登录状态的会员，每个账号只判定一次。「关闭」：不发放。「充值用户赠送」：判定时已有成功到账充值记录的会员才发放，之后充值不补发。「无需充值赠送」：不要求充值记录。奖励自动到账，需满足打码倍数要求方可提现。判定时机、配置来源、账变与统计等完整规则见《安装PWA/APP奖励配置 PRD》。
↳ 赠送金额条件必填数字输入选非「关闭」时展示且必填；须大于 0，最多两位小数，不设上限，超过两位的小数无法输入。为空保存提示「请输入赠送金额」，为 0 保存提示「赠送金额须大于0」。会员实际到账的彩金金额（固定值），与弹窗中「显示赠送金额」相互独立，两者可以不同。

安装引导弹窗触发下载或安装动作后均不会自动关闭：「0小时(强制安装)」下弹窗保留至页面刷新或跳转，「1~24小时」下需用户手动关闭。系统不判断用户是否已完成安装（PWA / APK 均不做已安装判定），弹窗按弹框间隔持续弹出，不因"已安装"而停止；仅顶部横幅保持可见，用户可点击「×」手动关闭（与《安装引导模块 PRD》口径一致）。
已安装唤起（二期新增）：用户在 H5 点击任意安装入口（顶部横幅 / 底部浮层 / 引导弹窗 / 下载页下载按钮）时，系统先尝试唤起该渠道对应的已安装 PWA / APK：已安装则直接打开并保持登录态无缝进入 App，不再重复下载；未安装则兜底回落到原下载安装流程；PWA+APK 按优先级（优先 PWA，不支持再 APK）判断后唤起。本逻辑仅作用于「点击安装」的瞬间，不改变弹窗弹出频率——仍不做持续性已安装判定，横幅 / 浮层 / 弹窗照常按时间点与间隔展示（与《安装引导模块 PRD》口径一致）。

点击表格操作列编辑图标后弹出，标题为「编辑渠道」。地区和所属商户字段置灰不可编辑，回填当前数据；渠道名称等其他字段均回填当前配置数据，渠道名称输入框右侧显示清除按钮（×）。所有配置项与新增渠道弹窗完全一致，提交后保存更新。

3.5.6 测试回传弹窗

点击表格操作列「Test」按钮后弹出，用于测试该渠道的埋点回传是否正常。

字段说明
渠道名称只读，自动填入当前渠道名称
类型只读，自动填入当前渠道的埋点类型
Pixel Id只读，自动填入当前渠道配置的Pixel Id（如有）
测试链接可编辑文本域，展示当前渠道的测试专用链接；修改不影响实际渠道链接，仅用于本次测试
页面提示：「[测试链接]只用于测试回传，测试成功后，请使用[渠道链接]进行投放」

3.5.7 事件说明弹窗

点击表格操作列「事件说明」图标后弹出（仅已定义回传事件清单的埋点类型显示此按钮，即 Facebook API / TK API / Kwai API / APK上架包 / IOS上架包；常规推广与 APK 不显示）。弹窗标题为该埋点类型名称，内容展示该类型的回传事件列表，每条格式为「中文事件名称 - 事件标识符」。三方API类型的具体事件内容以三方平台官方文档为准；上架包类型的事件清单由我方客户端埋点规范定义，见下方。

四、子页面二：推广效果报表

展示指定地区、商户、推广渠道在选定时间范围内的推广效果数据，分综合效果、直推效果、裂变效果三个维度呈现。数据每10分钟更新一次。

4.1 筛选区

字段控件说明
地区下拉单选默认当前账号授权地区
商户下拉单选随地区联动
推广渠道两层级联多选 + 全选第一层为推广商，点击展开第二层渠道列表；样式与批量替换「替换渠道」选择器一致；支持直接输入搜索
时间日期范围选择器默认当天；支持自定义起止日期

快捷筛选标签栏：展示当前商户下所有推广商，规则与推广渠道管理页一致。

4.2 数据展示

页面分三个数据块，字段完全一致。金额类字段精确到小数点后两位；充提差正数显示绿色，负数显示红色。

数据块说明
综合效果直推 + 裂变的合计数据
直推效果通过推广渠道直接注册的用户产生的数据
裂变效果通过已注册用户邀请带来的新用户产生的数据

各数据块字段：注册人数 / 首充人数 / 首充金额 / 充值人数 / 充值金额 / 提现人数 / 提现金额 / 充提差 / 提现手续费 / 投注人数 / 投注金额 / 有效投注 / 赠送金额

字段口径说明：「赠送金额」统计所有活动的奖励金额，即统计范围内各类活动发放给用户的奖励总额；其余字段的含义与统计口径均与「推广渠道报表」一致。
安装PWA/APP奖励同样计入「赠送金额」，归属会员的注册渠道，不计入会员安装时访问的渠道。
