一、概述

1.1 背景

活动列表中，已关闭活动不区分活动类型，统一提供「查看 / 编辑 / 开启」，存在以下问题：

  1. 过期活动开启后无法处理：活动时间已过期的已关闭活动点击「开启」后，状态变为已结束，仅剩「关闭」操作，无法编辑活动时间。
  2. 已关闭活动可修改配置：活动关闭后可编辑配置并重新开启，同一活动 ID 下存在多轮不同配置的领奖记录，统计与对账无法对应当时规则。
  3. 无法复用：复用历史活动只能修改原活动，无法基于原配置新建。
  4. 无法清理：仅草稿可删除，已关闭活动持续堆积在列表中。

1.2 目标

按活动类型的「单例型 / 多实例型」属性区分已关闭活动的操作：单例型关闭视为暂停，可编辑后重新开启；多实例型关闭视为归档，配置锁定，通过复制新建、通过删除清理。同时约束单例型活动在同一商户下只能存在一个。

1.3 范围

模块类型改动
活动类型属性新增活动类型增加「单例型 / 多实例型」属性，系统内置
活动列表 · 已结束修改操作增加「查看」
活动列表 · 已关闭 · 单例型修改操作不变；「开启」增加过期拦截；编辑保存后保持已关闭
活动列表 · 已关闭 · 多实例型修改操作由「查看 / 编辑 / 开启」改为「查看 / 复制 / 删除」

活动列表 · 草稿 / 待生效 / 进行中不变操作与现网一致

1.4 名词定义

名词定义
单例型活动同一商户下，该活动类型只能存在一个活动（不区分活动状态）。
多实例型活动同一商户下，该活动类型可同时存在多个活动（可按不同条件、时段、层级配置）。
活动状态草稿、待生效、进行中、已结束、已关闭，共五种。
活动时间已过期活动时间的结束时间早于当前时间，按商户所在时区判定。活动时间为「永久」的活动不会过期。

二、活动类型属性

活动类型的单例型 / 多实例型属性由系统按活动类型内置，商户后台不提供配置入口。

字段含义控件必填输入要求说明
实例类型标识该活动类型在同一商户下允许存在的活动数量无（系统内置）—取值：单例型 / 多实例型；每个活动类型固定一个取值，不可修改决定已关闭活动的可用操作（见 3.1）及新增活动保存校验（见第四章）

三、活动列表操作逻辑

3.1 操作按钮矩阵

活动状态单例型多实例型相比现网
草稿查看 / 编辑 / 发布 / 删除查看 / 编辑 / 发布 / 删除不变
待生效查看 / 编辑 / 关闭查看 / 编辑 / 关闭不变
进行中查看 / 编辑 / 关闭查看 / 编辑 / 关闭不变
已结束查看 / 关闭查看 / 关闭新增 查看
已关闭查看 / 编辑 / 开启查看 / 复制 / 删除多实例型：移除 编辑、开启；新增 复制、删除

操作以图标按钮展示，悬停显示文字提示（见第六章）。草稿、待生效、进行中的各项操作沿用现网规则，本文档不展开。

3.2 已结束 · 查看

  • 打开活动详情页，只读，与其他状态的查看页一致。

3.3 已结束 · 关闭

  • 点击后弹出二次确认，提示关闭后会员所有未领取奖励全部作废（文案见第六章）。
  • 确认后状态变为已关闭，按所属活动类型适用 3.1 已关闭规则。

3.4 已关闭 · 单例型 · 编辑

  • 打开编辑页，可编辑项与现网编辑页一致。
  • 保存后活动保持已关闭，不自动开启。

3.5 已关闭 · 单例型 · 开启

条件处理
活动时间未过期（含永久）弹出二次确认；确认后开启，状态按活动时间判定：开始时间晚于当前时间为待生效，否则为进行中。
活动时间已过期不执行开启，弹出拦截弹框。点击「去编辑」进入该活动编辑页；点击「取消」关闭弹框，活动保持已关闭。

3.6 已关闭 · 多实例型 · 复制

  • 点击后打开新增活动页，按原活动配置预填全部字段。
  • 「活动时间」「显示时间」清空，需重新选择；未选择活动时间时不允许保存。
  • 「活动名称」与原活动一致，不追加后缀。
  • 点击保存前不生成数据；关闭页面不产生新活动。
  • 保存后生成新的活动 ID，状态按新增活动规则判定。新活动与原活动无关联，原活动保持已关闭，数据不变。

3.7 已关闭 · 多实例型 · 删除

  • 点击后弹出二次确认（文案见第六章），确认后执行逻辑删除。
  • 删除后活动从活动列表移除，任何状态筛选（含「全部」）均不展示。
  • 活动统计、优惠统计、待审核奖励记录、已审核奖励记录中保留该活动的数据，可正常查询。

四、新增活动 · 单例型校验

项目规则
校验时机新增活动页点击「保存」时。
校验条件所选活动类型为单例型，且当前商户下该活动类型已存在活动。
判定范围已存在活动包括所有状态：草稿、待生效、进行中、已结束、已关闭。
校验不通过不保存，提示「只能创建一个{活动类型}活动」；停留在新增活动页，已填内容保留。
校验通过正常保存，生成新活动。

活动类型下拉框中单例型类型仍可选择，校验在保存时进行。

七、边界与异常

场景处理
永久活动开启活动时间为永久的已关闭单例型活动不判定过期，二次确认后开启为进行中。
过期判定时区按商户所在时区比较活动结束时间与当前时间。
拦截后去编辑编辑页保存后活动保持已关闭；需再次点击「开启」，重新执行过期判定。
复制中途退出新增活动页未保存即关闭，不生成新活动，原活动不受影响。
删除后的数据逻辑删除的活动不在活动列表展示；活动统计、优惠统计、待审核与已审核奖励记录照常展示该活动数据。
已结束活动关闭关闭后会员所有未领取奖励全部作废。
单例型新增校验只要当前商户下存在该类型的活动（任意状态）即校验不通过。
