一、需求背景

充值活动是平台以"充值"为核心奖励条件的存款激励活动,作为综合类活动新增到现有活动列表菜单中。运营人员可按不同活动条件配置阶梯奖励规则,引导会员完成充值,提升首充转化、充值总额与充值留存。

本活动支持三种活动条件,面向不同运营目标:

  • 首笔充值：面向周期内的首笔充值,提升首充转化。
  • 累计充值：周期内累计充值达阶梯即可叠加领取,拉动充值总额。
  • 连续天数充值：以连续充值天数为条件,培养持续充值习惯、提升留存。

四、后台功能说明

4.1 活动列表页

充值活动纳入现有活动列表菜单。活动类型筛选与列表新增"充值"；列表行支持查看 / 修改 / 删除。列表字段沿用现有活动列表：序号、活动ID、活动分类、活动名称、活动类型、活动条件、参与会员、稽核倍数、活动时间、显示时间、开启时间、活动状态、置顶、操作人、操作时间、操作。其中"活动条件"展示该充值活动配置的奖励条件（首笔充值 / 累计充值 / 连续天数充值）。

多活动并存：充值为活动模板，同一模板下允许同时创建并生效多个充值活动（例如"首笔充值奖励""每日累计充值奖励""每周连续充值奖励"可同时处于进行中），系统不限制同一时间仅一个充值活动生效；各活动独立配置、独立参与、独立发奖与统计。

4.6 统计口径与重置周期

  • 统计起点：统计从活动创建/生效时间起算，活动生效之前的历史充值不计入本活动。
  • 重置周期：重置方式决定首充/累计/连续的统计周期——不重置（持续累计）、每日（每天归零重新统计）、每周（每周归零重新统计）。连续天数充值不支持"每日"。

4.7 奖励领取、账变与提现打码

  • 领取方式：固定手动领取。
  • 领取判定：会员点击领取时，按申领终端限制、申领限制等公共规则进行判定与拦截提示（沿用现有活动的判定逻辑与提示文案）；不满足时按对应提示拦截，满足后方可领取。
  • 累计多档领取：各档为独立奖励、独立账变。点击领取时，一次领取当前所有"已达标未领"的档位（前台合并显示为可领取总额），领取后按档生成多条账变；不支持仅领取某一档、跳过其他档。
  • 提现打码：领取的奖励须按稽核方式（赠送部分 或 本金+赠送）完成稽核倍数对应的有效投注后方可提现。

4.8 奖励处理时序（作废/派发）

奖励作废设置处理时机结果
过期自动派发 / 过期作废绑定活动重置 / 结束边界，即时处理（如每日重置：参与当天未领，次日重置即处理）自动派发=到账；过期作废=作废不入账
保留天数自动派发 / 保留天数作废（过期天数 = N > 0）绑定保留天数，参与活动当天不计入；自动处理日 = 参与日 + 1 + 保留天数。保留期内会员可手动领取逾期未领：自动派发=到账；作废=作废不入账
过期天数 = 0 或空（奖励不过期）奖励永不过期，不触发自动派发 / 作废，会员在活动有效期内可随时手动领取始终可领，直至活动结束

奖励过期功能逻辑："奖励领取过期天数" = 0 或留空 → 奖励不过期、始终可领（是奖励生命周期的实际行为，规则第 2 条"一直保留"等文案随此显示）；针对保留天数类。过期类（过期作废 / 过期自动派发）在活动重置 / 结束边界过期处理，不使用过期天数。

4.9 编辑限制

编辑（修改/查看）已创建的充值活动时，活动分类、活动类型、领取时间、活动条件不可修改（置灰）；其余字段可编辑。

4.10 领取时间 / 奖励作废 —— 正常方案 与 本期临时方案 ★

领取时间与奖励作废的联动存在两套口径：正常方案 为待领取页上线后的完整能力；本期临时方案 为当前实际生效的配置限制。全文凡涉及每日/每周重置下的领取时间与奖励作废，均以本节为准。

⚠ 本期临时方案（待领取页上线前 · 当前生效）

背景："待领取"跨周期领取入口尚未上线。若每日 / 每周重置的活动使用"次日领取"或"保留天数"作废，会产生这样的奖励——活动重置进入新周期后，它仍在保留期内、但主页已是新周期、又没有待领取入口，导致玩家无处领取（保留天数作废还会直接损失）。

临时措施：对每日/每周重置的充值活动限制配置，使其只用"重置即处理、不跨周期"的安全组合：

重置方式正常方案（待领取页上线后）本期临时方案（当前生效）
不重置领取时间：次日 / 实时；奖励作废：四项均可选与正常方案一致（不受限；主页可持续领取，不存在跨周期问题）
每日 / 每周领取时间：次日 / 实时；奖励作废：四项均可选（跨周期未领奖励在"待领取"入口领取）领取时间锁定"实时领取"（禁用次日）；奖励作废仅可选"过期自动派发 / 过期作废"（禁用两个"保留天数"选项）
连续天数充值
（强制实时）		不重置 / 每周；奖励作废四项可选每周时奖励作废仅"过期"两项；不重置不受限

移除条件："待领取"跨周期领取入口（第 5.6 节）上线后，移除本临时限制，恢复正常方案的完整配置。

4.11 奖励状态流转

当前状态触发流转至
未达标充值达到档位/门槛可领取
可领取（实时）会员手动领取且通过领取判定已领取（到账，进入打码）
可领取（次日）未到"选择时间"次日待领 → 到点后转"可领取"
可领取 / 待领取有效期内未领取按奖励作废设置处理：过期自动派发/保留天数自动派发→到账；过期作废/保留天数作废→作废
连续天数·进行中当日累计充值达门槛有效充值天数 +1；断充则重置为 0
已领取完成稽核倍数打码可提现

4.12 异常与边界处理

  • 领取判定不通过：不满足申领终端限制、申领限制等条件时，拦截领取并按公共配置的提示文案提示（沿用公共配置）。
  • 重复领取：已领取的档位不可重复领取（按钮不可点）；累计已领档不再计入可领总额。
  • 活动关闭 / 下线：活动关闭后不再产生新奖励；已产生未领取的奖励按"奖励作废"设置处理（沿用公共规则）。
  • 连续断充：当日累计充值未达门槛不计入有效充值天数；断充后周期内连续天数从第 1 天重新开始。
  • 累计口径：领取奖励不扣减累计；统计起点为活动生效时间，活动生效前的历史充值不计入。
  • 并发 / 网络异常：领取结果以后台最终判定为准，前台按后台返回结果展示（沿用公共处理）。

4.13 权限说明

充值活动的新增、编辑、查看、开启/关闭等后台操作权限，沿用现有后台活动模块的权限体系（按角色/账号权限控制），本活动不新增独立权限项。

五、前台功能说明

5.1 页面结构

活动标题：前台页面展示的活动标题取自后台"活动名称"配置（系统默认或自定义），与 4.2 / 4.4 的系统默认标题一致——系统默认时随活动条件与重置方式变化（不重置为基础名，每日/每周带"每日"/"每周"前缀），前台按客户端语言显示对应中文/葡语文案（对照见第六章）。

三种活动条件的前台页面样式不同，需分别设计：

  • 首笔充值 / 累计充值：顶部 banner + 当前可领取总额徽标 + 进度文案（累计另显示"累计充值"金额与"还差 X 到档 Y"）+ 档位列表（充值金额 | 奖励金额）+ 领取按钮 + 活动规则。
  • 连续天数充值：顶部 banner（连续 N 天 + 大奖金额）+ "中断连续将重置进度"提示 + 连续进度（x/N）+ 天数轨道（天数标签 + 可滑动天数格 + 最后一天固定展示大奖）+ 领取按钮 + 活动规则。

未登录展示：会员未登录时，三种活动条件的页面均展示为各自的"未开始"基线视图（首笔 / 累计：可领取 R$0,00、进度从零、领取按钮不可点；连续天数：进度 0/N、无"今天"标记、天数格均未开始、领取按钮不可点），登录后再按会员实际进度渲染。

5.2 档位列表展示规则

首笔 / 累计模式下，页面中的档位列表（充值金额 → 奖励金额）为静态展示：各档位行样式固定，不随达标 / 可领 / 已领状态而改变样式。领取状态统一通过以下元素体现，而非改变档位行样式：

  • 顶部"当前可领取总额"（累计满足多档时为各档合计）。
  • 进度文案："还差 X 到下一档 Y"、"今日可领 X"。
  • 领取按钮的可点 / 不可点状态。

按活动条件分两类。首笔充值 / 累计充值按钮只有两态，且按钮文字始终为"领取"（不出现其他文字）：

5.5 连续天数页交互

  • 进度：显示 x/N。当日累计充值达门槛，当天格计为已完成；未达门槛则当天不计入。
  • 天数格四种状态（样式须区分，具体颜色以设计稿为准）：①过去·已完成（对勾，无边框）；②当天·已完成（对勾 + "今天"标识，须与"过去·已完成"区分）；③当天·未完成 / 进行中（进行中图标 + "今天"标识）；④未开始（锁图标）。当天达门槛时由状态③转为状态②。
  • 天数标签：天数较多时，天数按段展示为标签，点击标签快速定位到对应天数段。
  • 天数轨道：第 1 ~ N-1 天为可左右滑动的天数格，滑动不受天数标签限制（标签仅作快捷跳转）；最后一天（第 N 天）固定在最右侧，展示大奖金额。
  • 领取按钮三态：①领取·不可点——未集齐连续天数（未达标），按钮不可点，文字"领取"（Receber）；②领取·可点——已集齐 N 天、在开放时间内且未领取，按钮可点，文字"领取"（Receber）；③已领取·不可点——连续奖励已领取且周期尚未重置，按钮不可点，文字"已领取"（Resgatado）。周期重置后进度归零、按钮回到状态①。
  • 去充值跳转：连续未达标期间，进度行内提供"去充值"按钮，点击跳转到充值页，引导会员继续充值以延续连续天数（此时主领取按钮为状态①不可点）。

5.6 待领取 / 已领取 / 跨周期领取入口

  • 待领取：列出各活动未领取奖励，累计多档的每一档各占一行；提供"全部领取"一并领取。
  • 已领取记录：按时间列出已领取记录，累计多档各占一行（独立账变）。
  • 跨周期领取入口：保留天数类奖励与活动周期无关，可跨周期保留。当主活动页已进入新周期时，未领取的旧奖励仍在"待领取"入口内可领，直至保留期满按设置自动派发或作废。

说明：本节为 正常方案（待领取页上线后）的能力。本期临时方案 下，每日/每周重置已禁用"次日领取/保留天数"（见 4.10），不会产生跨周期滞留的奖励；"待领取"跨周期入口与本节能力随待领取页一并上线，届时移除 4.10 临时限制。

5.8 次日领取 · 提示切换逻辑

适用范围（受当前设置限制）：次日领取仅可配置于 「首笔充值 · 不重置」 与 「累计充值 · 不重置」，本逻辑仅适用这两种。（连续天数强制实时；每日 / 每周重置锁定实时、禁用次日。）

金额：今日可领 X = 已过开放时间、可即时领取且未领取的金额；待领 M = 已达标但未到开放时间的金额。顶部"可领取"徽标金额 = X。奖励的开放时间 = 达标日次日的〔选择时间〕（后台"次日领取 · 选择时间"配置值）。

提示三态（同一笔奖励，按当前时间相对其开放时间）

当前时间提示格式

格式统一为"〔次日 / 今日〕〔选择时间〕后可领取 R$金额"，随当天与否把"次日"换"今日"；到点后才变"今日可领"。触发点为〔选择时间〕，非 00:00、非系统重置时间。

领取与循环

  • 领取行为：领取把当前已开放的 X 领走（X→0），提示回到待领 M 的三态显示；顶部"可领取"回 R$0,00。
  • 首笔 · 不重置（单笔）：领取后即"已领取"态、可领取 R$0,00、按钮置灰，不循环。
  • 累计 · 不重置（多档叠加）：循环。X > 0 期间若再充值达更高档，新增金额只进 M、不改变 X，提示保持"今日可领 R$X"不变；领取 X 后才按三态显示待领 M。未领则各档开放后累积计入 X。
  • 未领 / 过期：开放后仍未领，按该活动"奖励作废"配置处理（见 4.8）；过期作废则金额移除、不再显示可领。须有达标奖励（X 或 M > 0）才有提示，未达标不切换。

过期作废彩金需要手动领取，过期后彩金将自动作废O bônus deve ser resgatado manualmente; após o prazo de validade, o bônus será automaticamente cancelado
过期自动派发彩金需要手动领取，过期后彩金将自动派发O bônus deve ser resgatado manualmente; após o prazo de validade, o bônus será distribuído automaticamente
保留天数自动派发（N 天）彩金需要手动领取，彩金保留 N 天后自动派发O bônus deve ser coletado manualmente e será distribuído automaticamente após N dias
保留天数作废（N 天）彩金需要手动领取，彩金保留 N 天后自动作废O bônus deve ser coletado manualmente e será cancelado após N dias
规则 3 · 提现稽核　【联动：稽核方式 + 稽核倍数 X】
赠送部分彩金（不含本金）需 X 倍有效投注才能提现O bônus (excluindo valor principal) requer X vezes de apostas válidas para sacar
本金+赠送本金+彩金需 X 倍有效投注才能提现O bônus (incluindo valor principal) requer X vezes de apostas válidas para sacar
规则 4 / 5 · 固定（不联动）
固定仅限账号本人进行正常的人为操作，否则将取消或扣除奖励、冻结、甚至拉入黑名单Somente operações humanas normais pelo proprietário da conta são permitidas, caso contrário, as recompensas serão canceladas ou deduzidas, congeladas ou até mesmo colocadas na lista negra
固定为避免文字理解差异，平台将保留本活动最终解释权Para evitar diferenças na compreensão do texto, a plataforma reserva-se o direito de interpretação final deste evento
