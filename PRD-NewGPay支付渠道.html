一、需求背景与范围

H5 存款页与取款页当前仅接入 BESTPAY 单一支付渠道，资金通道与收款方式均依赖该渠道。为拓宽巴西站的入金与出金通道、降低单一渠道故障与风控波动带来的影响，本期新增第三方支付渠道 NEWGPAY，在存款页与取款页的渠道区与 BESTPAY 并列提供给会员选择。

NEWGPAY 采用代币结算模式：会员在 NewGPay 侧持有 NGC 代币余额，充值时由 NGC 钱包扣币、平台按 1 NGC = 1 R$ 入账；提现时由平台扣减账户余额、按 1:1 入账至会员的 NGC 钱包。由于资金直接在 NGC 钱包之间流转，该渠道不需要会员填写 CPF、手机号等收款信息，这是其与 BESTPAY 在前台表单结构上的最主要差异。

本次需求范围

模块范围对应章节
前台 H5 存款页渠道区新增 NEWGPAY；NewGPay 钱包卡片（余额 / 购买入口 / 卡内要点条）；快捷与自定义金额；渠道赠送角标与实际到账计算；余额不足引导购买；同步充值结果。原说明折叠条取消，改由《NewGPay新手引导 PRD》承担。第四章

二、名词解释

名词说明
NewGPay本期接入的第三方支付渠道。前台渠道按钮名称统一显示为 NEWGPAY（全大写），与 BESTPAY 的书写规则保持一致。
NGCNewGPay 侧的结算代币。与平台货币固定 1:1 换算（1 NGC = 1 R$），该汇率在存款页与取款页均固定展示。
NGC 钱包会员在 NewGPay 侧的代币账户，由唯一的钱包地址标识。会员首次进入取款页并选择 NEWGPAY 时由系统自动开通，无需会员手动注册。
NGC 余额会员 NGC 钱包内的可用代币数量，由平台实时向 NewGPay 查询获得，非平台账户余额。
账户余额会员在平台的可用余额，单位 R$。存款入账与提现扣款的对象。
赠送比例通过 NEWGPAY 渠道充值时平台额外赠送的比例，由后台配置，默认 0。实际到账金额 ＝ 充值金额 ×（1 + 赠送比例）。
有效流水平台现有的提现流水（打码量）规则。本渠道沿用平台既有口径与计算方式，不新增规则。

四、前台存款页 —— NEWGPAY 渠道

4.1 渠道选择区

  1. 展示形式：在「在线充值」Tab 下的渠道区，NEWGPAY 与 BESTPAY 并列横向排列，互斥单选，顺序由后台配置。
  2. 切换行为：点击渠道按钮仅替换下方内容区，不跳转页面、不清空已加载的钱包数据。页面默认选中渠道由后台排序的首个可用渠道决定。
  3. 可见性：渠道的上下线状态与可见会员层级由后台配置；当前会员不可见时，该渠道按钮不渲染（而非置灰）。若 NEWGPAY 为唯一可用渠道，渠道区仍保留并呈选中态。
  4. 赠送角标：当后台配置的赠送比例大于 0 时，NEWGPAY 按钮右上角显示角标，内容为「+N%」，N 取后台配置的赠送比例；赠送比例为 0 时不显示角标。角标仅在存款页展示，取款页不展示。

4.2 NewGPay 钱包卡片

渠道内容区顶部为 NewGPay 钱包卡片，三行结构，自上而下为：标题行、余额行、卡内要点条。

元素逻辑说明
标题行渠道图标 + 标题「NewGPay 数字钱包」。汇率角标由本行移入卡内要点条，标题行右侧不再放置元素。
NGC 余额进入渠道时实时向 NewGPay 查询并展示，格式为「数值 + NGC」。数值按客户端语言的千分位规则格式化。
加载失败态查询失败时余额位显示「--」，其下方显示「加载失败，点击重试」，点击后重新发起查询。此状态下点击「立即存款」不提交，轻提示同一文案。
购买NGC点击在 App 内 WebView 打开 NewGPay 买币页，详见第六章。

卡内要点条

卡片底部单行三栏等宽，栏间以竖线分隔，每栏为图标加一行文案。

栏位文案说明
第 1 栏1 NGC = 1 R$固定汇率，使用锁形图标表达比例锁定。该信息原位于标题行右侧的角标，本次移入要点条，避免同一卡片内重复展示。
第 2 栏可提回钱包说明 NGC 并非单向消耗，可通过取款页转回 NewGPay 钱包。
第 3 栏新手教程可点入口，品牌蓝加下划线，带扫光动效。点击重播存款引导，规则详见《NewGPay新手引导 PRD》第六章。

原「秒级到账」「加密安全」两栏与卡片下方的说明折叠条（收起态显示「什么是 NGC？如何获得？」）本次一并取消。折叠条承担的「NGC 是什么、怎么获得」说明，已由新手引导的品牌介绍屏与买 NGC 四步演示完整覆盖，且后者用录屏演示了 NewGPay 侧的真实操作，信息量远高于一段折叠文字。保留两者会形成两个并列的说明入口。

4.3 充值金额选择与输入

  1. 快捷金额：标题「快捷金额」，档位数量与取值由后台配置，单位 NGC。按配置顺序以三列栅格依次排列，与取款页保持一致。档位数值保留两位小数展示（如 5,00 NGC、1.000,00 NGC），与 NGC 作为代币金额的精度一致；格式沿用 pt-BR 规范，点作千分位、逗号作小数位。点击某档位即选中该档位并将金额回填至自定义输入框；手动修改输入框内容后，已选中的档位取消选中态。
  2. 自定义金额：标题「自定义充值金额」，输入框前缀固定显示单位 NGC，键盘类型为数字键盘，仅允许输入数字与小数分隔符。
  3. 限额提示：输入框下方常驻显示「单笔限额 {最低} NGC - {最高} NGC」，取值由后台配置。
  4. 汇率提示：金额区下方固定展示「1 NGC = 1 R$」。
  5. 按钮状态：「立即存款」在输入金额为空或为 0 时置灰（不可点击），输入有效金额后激活。NGC 余额为 0 或不足不影响按钮激活状态，该校验在点击后以弹窗形式引导，不以置灰阻断（避免会员误判为渠道不可用而放弃充值）。

4.4 赠送比例与实际到账

  1. 赠送比例由后台配置，默认 0。
  2. 金额区下方始终展示「实际到账金额：{数值}」，数值 ＝ 输入金额 ×（1 + 赠送比例），保留 2 位小数。输入金额为空或为 0 时该行不展示数值。
  3. 赠送比例为 0 时该行仍展示，数值与输入金额相等。

4.5 提交与结果处理

点击「立即存款」后按以下顺序校验，任一环节不通过即中止提交：

顺序校验项未通过时的处理
1NGC 余额是否加载成功轻提示「加载失败，点击重试」。
2金额是否不低于单笔最低限额轻提示「最低充值 {最低} NGC」。
3金额是否不高于单笔最高限额轻提示「单笔最高 {最高} NGC」。
4NGC 余额是否为 0弹窗「NGC 余额为 0」，正文告知无法完成充值并询问是否购买；按钮为「取消」与「立即购买」，点击后者进入买币页。
5NGC 余额是否大于等于充值金额弹窗「余额不足」，正文告知当前余额不足以完成本次充值；按钮为「取消」与「去购买」，点击后者进入买币页。

校验全部通过后发起提交，按钮进入处理中状态（置灰、文案改为「处理中...」）以防重复提交。

  1. 成功：本渠道为同步返回。轻提示「存款成功」，清空输入框与已选档位，刷新 NGC 余额与账户余额，随后自动返回会员进入钱包页之前所在的一级页（规则见《存款页优化说明（PIX / NewGPay）》5.2）。此处与 BESTPAY 不同：BESTPAY 为 PIX 扫码支付，提交后跳转站内收银页等待会员付款，见《BESTPAY 收银页站内化 PRD》6.1。
  2. 失败：轻提示渠道返回的失败原因，按钮恢复可点击状态，输入内容保留。

五、前台取款页 —— NEWGPAY 渠道

5.1 渠道选择区与账户信息

  1. 渠道区的展示形式、互斥单选、切换行为与可见性规则与 5.1 一致；取款页不展示赠送角标。
  2. 页面顶部沿用现有的「账户余额：R$ XX」展示行，不随渠道切换变化。
  3. 导航栏右侧沿用现有的取款记录入口。

5.2 NewGPay 钱包卡片

渠道内容区顶部为 NewGPay 钱包卡片，结构与 4.2 保持一致：标题行、余额行、卡内要点条，仅第三行的栏位内容与按钮文案不同。

元素逻辑说明
标题行渠道图标 + 标题「NewGPay 数字钱包」，右侧不放置元素。
钱包地址本次取消，前台不再展示。地址属于技术标识，对会员无操作价值，且完整展示会占据两行高度并带来抄写、误读与客诉风险。会员通过「进入钱包」按钮即可在 NewGPay 侧看到自己的账户，无需在本站阅读地址。
自动开通未开通 NewGPay 钱包的会员进入取款页并选择 NEWGPAY 时由系统自动开通，无空状态、无开通引导页。开通动作本身对会员不可见。
NGC 余额实时查询并展示，格式与加载失败态的处理与 4.2 一致。该余额为参考信息，不参与提现金额校验。
进入钱包点击在 App 内 WebView 打开 NewGPay 钱包首页，详见第六章。该按钮同时是提款引导第 4 步的高亮对象，是本站交接到 NewGPay 的唯一出口。

卡内要点条

栏位文案说明
第 1 栏1 NGC = 1 R$与存款页同一栏位、同一锁形图标。
第 2 栏PIX 收款说明在 NewGPay 侧卖出 NGC 后，款项经 PIX 到账。
第 3 栏新手教程可点入口，点击重播提款引导，规则详见《NewGPay新手引导 PRD》第六章。

原约定的「首次选择 NEWGPAY 渠道时弹出三步到账说明」本次取消。该说明的内容（金额先转入 NewGPay 钱包、需自行卖出、卖出后到账 PIX 账户）已由提款引导的页内四步高亮逐步呈现，并用录屏演示了卖出的真实操作。原弹窗为纯文字且只出现一次，会员读过即忘，是「转出后不去卖、资金滞留钱包」这类客诉的主要成因。

5.3 提款方式与收款信息区块的隐藏

选中 NEWGPAY 后，取款页的「提款方式」选择区（PHONE / CPF）及姓名、手机号码、CPF ID 三项收款信息字段整块隐藏。原因是本渠道资金直接入账至会员 NGC 钱包，不依赖 PIX 收款标识。

该隐藏仅作用于 NEWGPAY 渠道内容区。切回 BESTPAY 时上述区块正常展示，已填写或已绑定的提现资料不受影响，亦不因本渠道的使用而产生绑定或占用。相关绑定与唯一性校验规则见《增加Phone提款方式 PRD》第六章。

5.4 有效流水校验

  1. 沿用平台现有有效流水规则与计算口径，本渠道不新增规则。
  2. 已达标时：流水提示行整行不展示（「提款需投注 R$ XX」文案与「查看详情」链接一并隐藏）。
  3. 未达标时：在账户余额行下方展示「提款需投注 R$ XX」及右侧「查看详情」链接，点击展示流水规则说明。
  4. 未达标时「立即取款」按钮仍为激活状态，点击后轻提示「有效流水未达标，无法提现」并中止提交，与平台现有渠道的交互保持一致。

5.5 提款金额选择与输入

  1. 快捷金额：标题「提款金额」，沿用平台现有档位，按配置顺序以三列栅格排列，单位 R$。点击档位即回填至输入框，手动修改输入框后档位取消选中态。
  2. 金额输入：输入框前缀固定显示单位 R$，键盘类型为数字键盘。
  3. 「全部」快填：输入框右侧提供「全部」按钮，点击后将可提金额一键填入，取值为「账户可提余额」与「单笔最高限额」中的较小值。
  4. 限额提示：输入框下方常驻显示「单笔限额 R$ {最低} - R$ {最高}」，NEWGPAY 的限额独立配置，不沿用 BESTPAY 的取值。
  5. 单位与换算：前台金额统一以 R$ 展示与输入，底层按 1:1 换算为 NGC 入账。金额区下方固定展示「1 NGC = 1 R$」。
  6. 按钮状态：「立即取款」在输入金额为空或为 0 时置灰，输入有效金额后激活。
  7. 本渠道不提供金额滑块。

5.6 提交与结果处理

点击「立即取款」后按以下顺序校验，任一环节不通过即中止提交：

顺序校验项未通过时的处理
1有效流水是否已达标轻提示「有效流水未达标，无法提现」。
2金额是否不低于单笔最低限额轻提示「最低提款 R$ {最低}」。
3金额是否不高于单笔最高限额轻提示「单笔最高 R$ {最高}」。
4金额是否不超过账户可提余额轻提示「可提余额不足」。

校验全部通过后发起提交，按钮进入处理中状态（置灰、文案改为「处理中...」）以防重复提交。

  1. 成功：扣减账户余额并按 1:1 生成入账至会员 NGC 钱包的提现订单。轻提示「提交成功，请等待审核」，随后跳转取款记录页，该笔订单状态为「审核中」，渠道显示为 NEWGPAY。
  2. 无手续费：本渠道不收取提现手续费，因此取款页不展示「实际到账」行。
  3. 失败：轻提示失败原因，按钮恢复可点击状态，输入内容保留，账户余额不变动。

六、NewGPay 钱包 WebView

入口目标页面返回后的刷新范围
存款页「购买NGC」NewGPay 买币页刷新 NGC 余额。
存款页弹窗「立即购买」/「去购买」NewGPay 买币页刷新 NGC 余额；关闭弹窗，输入内容保留。
取款页「进入钱包」NewGPay 钱包首页同时刷新 NGC 余额与平台账户余额（会员可能在钱包内完成影响两者的操作）。
  1. 统一在 App 内 WebView 打开，不跳出至外部浏览器。
  2. 页面内容归属：买币页与钱包首页的页面内容由 NewGPay 维护，平台不参与设计与文案。其中买币页顶部为渠道信息区（品牌名与定位、一句话用途说明、到账速度 / 安全性 / 汇率三项要点），此处列出仅用于说明会员在该页所见，不属平台交付范围，相关文案亦不纳入第七章的中葡对照表。
  3. WebView 顶部提供返回栏（返回按钮 + 页面标题），标题取对应入口的按钮文案。
  4. 返回平台页面后按上表范围刷新，刷新完成后轻提示「余额已更新」；刷新失败时余额位按 5.2 的加载失败态处理。

八、边界与异常处理

场景处理方式
NGC 余额查询超时或失败余额位显示「--」并展示「加载失败，点击重试」；折叠说明条内容不展示；提交时中止并轻提示同一文案。点击重试重新发起查询。
NGC 钱包自动开通失败取款页 NEWGPAY 渠道内容区展示失败提示与重试入口，「立即取款」置灰；渠道区仍保留，会员可切换至其他渠道。
渠道在会员停留页面期间被后台下线提交时由服务端拦截并返回渠道不可用，前台轻提示并刷新渠道区（该渠道按钮不再渲染，自动切换至首个可用渠道）。
重复提交提交期间按钮置灰并显示「处理中...」，直至接口返回或超时后方可再次点击。
充值提交后渠道返回超时按失败处理，轻提示失败原因并恢复按钮，不扣减 NGC、不入账；以渠道最终对账结果为准。
金额输入非法字符或多个小数分隔符输入层即过滤，不进入校验流程。
输入金额超出限额或可提余额按 5.5 / 6.6 的校验顺序轻提示对应文案并中止提交，不清空输入内容。
「全部」填入后账户余额发生变化以提交时的服务端校验为准；超出可提余额则轻提示「可提余额不足」。
赠送比例在会员停留页面期间被修改以提交时服务端取到的配置为准；若与前台展示的「实际到账金额」不一致，按服务端结果入账，刷新后的余额即为准确值。
WebView 加载失败或会员中途返回返回平台页面后仍按本章的范围刷新余额；若无变化则余额保持原值，不做额外提示。
会员未登录或登录态失效沿用平台现有处理，跳转登录流程。
