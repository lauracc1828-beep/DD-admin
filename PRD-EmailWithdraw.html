一、需求背景与范围

H5 取款页现支持 CPF、PHONE 两种 PIX 提款方式。PIX 收款标识还包括邮箱，为覆盖使用邮箱作为 PIX Key 的会员，新增 EMAIL 提款方式。EMAIL 的配置、展示、保存、校验与报表体现均沿用 PHONE 的现有处理方式，提款方式配置、解锁判定、提款信息保存与锁定等通用规则见《增加Phone提款方式 PRD》，本文只描述 EMAIL 带来的新增与变化。

本次需求范围

模块范围对应章节
后台配置提现管理 → 提款方式配置新增「邮箱 / EMAIL」；其他提现配置的绑定数量上限覆盖提现邮箱。第四章
H5 前台收款信息弹窗新增 EMAIL 方式及「邮箱」字段；输入校验；保存与回填；已保存收款信息卡片展示；安全中心「提现账号管理」页显示提现邮箱。第五章

二、名词解释

术语说明
EMAIL本次新增的提款方式 CODE，对应 PIX Key 类型「邮箱」。前台按钮文案、后台账户类型取值均直接显示 EMAIL，语言无关。
提现邮箱会员用于 PIX 收款的邮箱，存放在会员提现账号中。与会员详情「个人资料」中的邮箱地址（账号绑定邮箱）相互独立，互不读取、互不同步。
账户类型提款订单所用的 PIX Key 类型，取值 CPF / PHONE / EMAIL。
提款账号提款订单所用的 PIX Key 值：CPF 单为 CPF ID，PHONE 单为手机号，EMAIL 单为提现邮箱。
提现邮箱脱敏@ 前的部分保留前 3 位，其后接 *****，@ 及域名完整显示。规则见第九章。

邮箱输入框—占位「请输入邮箱」；最多 64 位；失焦和保存时校验，为空提示「请输入邮箱」，格式不符提示「邮箱无效」
提交拦截CPF / 手机号达上限时拦截提现邮箱达上限时拦截，提示「该邮箱绑定次数已达上限」

补充说明

字段占位文案规则

  • 保存与回填规则见 5.3 节。

5.2 提现邮箱输入与校验

项规则
长度最多 64 个字符，超出部分无法输入。
预处理保存前自动去除首尾空格；大小写按会员输入原样保存。
格式同时满足：① 不含空格；② 有且只有一个 @，且 @ 前后均不为空；③ @ 之后至少包含一个「.」，且「.」不在域名首尾。
校验时机输入框失焦时及点击「保存」时校验；不通过时字段下方显示红字，「保存」不生效。
错误提示为空：请输入邮箱；格式不符：邮箱无效。

5.3 保存与回填

沿用《增加Phone提款方式 PRD》5.2 节规则，提现邮箱与手机号同等处理：

  • 在收款信息弹窗点击「保存」只在当前取款页生效，用于本次提交提款；刷新或离开取款页后，未提款成功的信息不保留，需重新填写。
  • 会员此前未保存提款信息时，以 EMAIL 方式提款成功后，本次填写的姓名、提现邮箱、CPF ID 写入会员提现账号并锁定；订单在审核中、被拒绝或罚没时均不保存。
  • 会员此前已保存姓名、CPF ID 时，选择 EMAIL 自动带入并锁定，只需填写邮箱；提款成功后提现邮箱一并保存并锁定。
  • 已保存提现邮箱的会员再次选择 EMAIL 时，邮箱自动带入且不可修改。

位置现状改动

  • 右侧「修改」入口沿用现有交互；脱敏规则见 9.1 节。

5.5 安全中心 → 提现账号管理

入口：我的 → 安全中心 → 提现账号管理 → 安全验证（输入提现密码）→ 提现账号管理页；入口与安全验证不变

位置现状改动
展示字段姓名 / CPF ID / 手机号码，固定展示在手机号码下方新增 邮箱，与手机号码一样固定展示
邮箱 · 已保存—只读，显示提现邮箱脱敏，如 qat*****@gmail.com
邮箱 · 未保存—可填写，占位「请输入邮箱」，输入规则同 5.2 节
保存校验按《增加Phone提款方式 PRD》第七章校验 CPF / 手机号绑定上限、本人审核中提款提现邮箱纳入绑定上限校验，提示「该 CPF / 手机号 / 邮箱绑定次数已达上限」

补充说明

  • 四个字段的显示与后台「提款方式配置」中各方式的状态、解锁条件无关。
  • 已保存的字段只读：姓名完整显示；CPF ID、手机号码沿用现网脱敏（前 3 位 + 6 个 * + 后 2 位，手机号码前带 +55）；邮箱按 9.1 节。
  • 未保存的字段可填写；姓名与 CPF ID 同时未保存时一起填写。存在未保存字段时页面底部显示「保存」，全部已保存时不显示。
  • 点击「保存」先做字段格式校验，再按第八章校验本人审核中提款与绑定占用上限，拦截时分别提示「提款审核中，暂时无法保存」「该 CPF / 手机号 / 邮箱绑定次数已达上限」；保存成功后字段转为只读并提示「保存成功」。
  • 姓名与 CPF ID 已保存时，页面底部提示「如需修改提现账号，联系客服」，「联系客服」可点击跳转客服。
  • 安全中心「提现账号管理」右侧：未保存提现账号时显示「未设置」，已保存时显示「已设置」。

八、提现资料绑定数量与唯一性校验

沿用《增加Phone提款方式 PRD》第七章，提现邮箱与 CPF、手机号同等纳入：

项规则
统计口径某提现邮箱的占用数 = 已保存该提现邮箱的会员数 + 审核中提款订单里使用该提现邮箱的会员数（按会员去重）。
相同判定去除首尾空格后比较，不区分大小写（如 QA@Gmail.com 与 qa@gmail.com 视为同一提现邮箱）。
H5 取款页提交提现提现邮箱占用数（不含本人）已达上限时不允许提交，提示「该邮箱绑定次数已达上限」。
H5 安全中心 → 提现账号管理保存本人存在审核中提款订单时不允许保存，提示「提款审核中，暂时无法保存」；提现邮箱占用数（不含本人）已达上限时不允许保存，提示「该 CPF / 手机号 / 邮箱绑定次数已达上限」。
会员详情保存本人存在审核中提款订单时不允许保存，提示「提款审核中，暂时无法保存」；提现邮箱占用数（不含本人）已达上限时不允许保存，提示「该 CPF / 手机号 / 邮箱绑定次数已达上限」。
释放运营在会员详情删除或更换会员的提现邮箱后，原提现邮箱的占用随即释放。
不限制「相同提现资料可同时绑定会员数量」= 0 时不做占用上限校验。

九、脱敏与搜索规则

9.1 提现邮箱脱敏

@ 前部分长度显示示例
≥ 3 位前 3 位 + ***** + @域名qatest@gmail.com → qat*****@gmail.com
< 3 位全部显示 + ***** + @域名qa@gmail.com → qa*****@gmail.com

脱敏用于：H5 已保存收款信息卡片、H5 提现账号管理页、总出款记录提款账号列、订单明细提现账号信息。会员详情、个人资料弹窗的提现账号显示完整提现邮箱。

9.2 搜索匹配

总出款记录「提款账号」与会员列表「提现邮箱」查询：输入完整提现邮箱精确匹配，去除首尾空格、不区分大小写；不支持部分匹配。

十、导出

待审核出款订单、已审核出款订单、总出款记录的导出文件随列表同步：账户类型列支持 EMAIL 取值，提款账号列 EMAIL 订单输出提现邮箱脱敏，提款信息内容与列表一致。导出的其他字段与逻辑不变。

十二、边界与异常处理

场景处理
EMAIL 被关闭，或会员不再满足 EMAIL 解锁条件，而会员当前提款方式为 EMAIL收款信息弹窗不展示 EMAIL；会员需选择其他可用方式，已保存的姓名、CPF ID 自动带入并锁定。已保存的提现邮箱保留在会员提现账号中，EMAIL 恢复可用后仍可直接使用。
EMAIL 订单提交后 EMAIL 被关闭已生成的订单按原账户类型 EMAIL 正常审核与出款，报表显示不受影响。
会员首次以 EMAIL 方式填写并提交提款，订单被拒绝或罚没本次填写的姓名、提现邮箱、CPF ID 均不保存；会员下次提款需重新填写。
会员粘贴超过 64 个字符的邮箱只保留前 64 个字符，并按格式规则校验。
会员输入的提现邮箱与账号绑定邮箱不同允许，两者相互独立。
两名会员的提现邮箱仅大小写不同视为同一提现邮箱，按第八章计入占用数。
提款审核中，运营在会员详情修改提现邮箱不允许保存，提示「提款审核中，暂时无法保存」；该订单显示的提现账号信息以下单时为准。
