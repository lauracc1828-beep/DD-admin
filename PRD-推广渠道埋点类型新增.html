推广渠道埋点类型新增 · PRD
📄 版本：v1.0 ✏️ 作者：Laura 📅 更新日期：2026-10-02

一、需求概述

推广渠道管理模块现有四种埋点类型（常规推广、Facebook API、TK API、Kwai API），均面向 H5 渠道链接的投放与回传。本需求新增三种面向独立安装包的埋点类型：APK上架包（商户自行封装并上架谷歌商店的马甲包，SD=6）、iOS上架包（商户自行封装并上架苹果商店的安装包，SD=4）、APK（H5 套壳包，打包指定 URL 后由商户自行分发）。

三种新埋点与现有埋点的本质差异在于用户已处于 App 环境内，无需再被引导下载安装，因此落地指向的生效范围、下载按钮与安装引导的前台表现均与常规推广不同。本需求包含后台配置与前台交互两部分。

二、后台配置

2.1 埋点类型新增选项

「埋点类型」为渠道的必填字段，下拉单选，决定该渠道的数据追踪方式与前台落地行为。本需求在现有选项基础上新增以下三项，新增选项排列于现有四项之后。

新增选项展开字段事件说明选项说明
APK上架包 全渠道回传 kwai ID 非必填，见 2.2 ✅ 有见 2.3 商户自行封装并上架谷歌商店的马甲包，SD=6。用户可在谷歌商店中按名称搜索到该包并安装，安装后在 App 内加载落地页。
iOS上架包 无 ✅ 有见 2.3 商户自行封装并上架苹果商店的安装包，SD=4。用户从苹果商店安装后在 App 内加载落地页。
APK 无 ❌ 无 H5 套壳包，打包指定 URL 生成安装包，由商户自行分发，不经应用商店。用户安装后在 App 内加载打包的 URL。
三种新埋点均不需要填写 Pixel ID 与访问令牌 TOKEN，不涉及 test_event_code 事件测试字段。

2.2 APK上架包专属字段

字段必填控件展示条件字段说明
全渠道回传 kwai ID 非必填 文本输入 埋点类型选择「APK上架包」时展示；切换为其他埋点类型时隐藏并清空已填内容 该上架包全渠道数据回传至快手平台的标识，由投流方提供。留空表示不做快手全渠道回传，不影响该渠道在我方后台的数据统计。

2.3 事件说明

事件说明用于展示该埋点类型的回传事件清单，内容格式为「中文事件名称 - 事件标识符」，具体以三方平台官方文档为准。入口有两处，均仅对 APK上架包与 iOS上架包展示：

入口位置展示条件交互说明
渠道表单内 新增渠道 / 编辑渠道 / 批量新增渠道弹窗中，「埋点类型」选择 APK上架包 或 IOS上架包 后展示；选择 APK 或其他埋点类型时不展示 在埋点类型字段下方展示事件说明入口，供运营在配置渠道时直接查看该类型的回传事件清单。
渠道列表操作列 渠道埋点类型为 APK上架包 或 IOS上架包 时展示「说明」按钮；埋点类型为 APK 时不展示 点击弹出事件说明弹窗，标题为该埋点类型名称，内容为回传事件列表，与表单内展示的内容一致。

回传事件清单

埋点类型回传事件（共 8 项）
APK上架包注册 - register；注册点击 - registerClick；登录 - login；登出 - logout；开始游戏 - enterGame；拉起订单 - rechargeClick；首充 - firstrecharge；充值 - recharge
iOS上架包同 APK上架包，共 8 项
APK不涉及回传事件，两处入口均不展示

2.4 测试回传弹窗

点击渠道列表操作列「Test」按钮后弹出，用于测试该渠道的埋点回传是否正常。三种新埋点下弹窗字段表现如下：

字段三种新埋点下表现说明
渠道名称只读回填自动填入当前渠道名称。
类型只读回填自动填入当前渠道的埋点类型，即 APK上架包 / IOS上架包 / APK。
Pixel Id保留字段，空值置灰三种新埋点无 Pixel ID 概念，该字段保留展示但内容为空且不可编辑，以维持弹窗布局与现有埋点一致。
测试链接可编辑用于测试回传的链接，测试成功后应使用渠道链接进行投放。

2.5 影响范围

三个新增埋点选项需在以下位置同步生效，选项顺序与文案保持一致：渠道列表筛选区的「埋点类型」下拉（含「全部」选项）、新增渠道弹窗、编辑渠道弹窗、批量新增渠道弹窗（三者渠道设置字段一致）、渠道列表数据表格的「埋点类型」列展示、测试回传弹窗的「类型」只读字段，以及推广效果报表的埋点类型维度。现有四种埋点类型的字段展开、事件说明与前台行为不受本需求影响。

三、前台交互

3.1 落地指向生效范围

三种新埋点下，落地指向的生效范围与常规推广不同，具体如下。

落地指向是否生效适用埋点前台表现
官网首页 / 官网注册页 / 主域名 ✅ 生效 三种新埋点 域名跳转按所选跳转域名正常生效，用户可正常落地至对应 H5 页面。三种落地指向的交互表现一致。
仿谷歌页 / 防封下载页 ❌ 不生效 三种新埋点 域名跳转正常，下载页可正常打开，但页面上的安装按钮点击不生效。该组合无实际投放价值，运营配置新埋点渠道时不应选择下载页类落地指向。

3.2 下载按钮

三种新埋点下，安卓端与 iOS 端均不展示「下载按钮」对应的两个前台入口——顶部固定横幅与底部安装浮层。用户已处于 App 环境内，无需再引导下载，后台「下载按钮」开关的配置不作用于新埋点渠道。

3.3 安装引导

安装引导弹窗的生效情况按埋点类型与终端区分，仅 APK上架包的安卓端生效。

埋点类型终端是否生效前台表现
APK上架包 安卓 ✅ 生效 按后台安卓 Tab 配置的弹框内容、弹框时间点与弹框间隔时间正常弹出安装引导弹窗，用户可正常跳转并完成安装。弹框安装类型配置为 pwa(快速安装) / apk(需要自己封装) / pwa(优先)+apk(推荐使用) 时，实际可安装内容与配置一致；使用非 Chrome 浏览器点击安装时，唤起 Chrome 的逻辑正常生效。
iOS ❌ 不生效 不弹出安装引导弹窗。iOS 设备无法安装 APK 文件，弹出引导将导致无效下载，故 iOS 端不展示任何安装引导。Safari 与 Chrome 表现一致。
iOS上架包 安卓 / iOS ❌ 不生效 两端均不弹出安装引导弹窗。iOS 端 Safari 与 Chrome 表现一致。
APK 安卓 / iOS ❌ 不生效 两端均不弹出安装引导弹窗。
后台「渠道设置」中安卓 Tab 与苹果 Tab 的字段仍可正常配置与保存，但仅 APK上架包的安卓 Tab 配置会作用于前台；其余组合的配置不生效。

四、验收要点

  1. 埋点类型字段：筛选区、新增 / 编辑 / 批量新增渠道弹窗的「埋点类型」下拉均展示 APK上架包、IOS上架包、APK 三个新选项，文案与顺序一致；渠道列表「埋点类型」列与测试回传弹窗「类型」字段可正确展示三种新类型。
  2. 专属字段：选择 APK上架包 展开「全渠道回传 kwai ID」且为非必填；切换至其他埋点类型时该字段隐藏并清空；iOS上架包与 APK 不展开任何子字段。
  3. 事件说明：表单内选择 APK上架包 或 IOS上架包 后展示事件说明，内容为 8 项回传事件；渠道列表操作列对这两类渠道展示「说明」按钮，弹窗标题为埋点类型名称、内容与表单内一致；APK 两处均不展示。
  4. 测试回传弹窗：三种新埋点下 Pixel Id 字段保留展示、内容为空且置灰不可编辑，渠道名称与类型正确只读回填。
  5. 落地指向：三种新埋点配置官网首页 / 官网注册页 / 主域名时，安卓与 iOS 均可正常落地、域名跳转正常；配置仿谷歌页 / 防封下载页时页面可打开但安装按钮点击不生效。
  6. 下载按钮：三种新埋点在三种 H5 落地指向下，安卓与 iOS 均不展示顶部横幅与底部安装浮层。
  7. 安装引导：仅 APK上架包的安卓端弹出并可正常安装，弹框安装类型三种配置均可正确安装、非 Chrome 浏览器唤起 Chrome 正常；APK上架包 iOS 端、iOS上架包两端、APK 两端均不弹出，iOS 端需分别验证 Safari 与 Chrome。
  8. 回归：常规推广、Facebook API、TK API、Kwai API 四种现有埋点的字段展开、事件说明、测试回传弹窗与前台下载按钮 / 安装引导行为均不受影响。
