推广渠道埋点类型新增 · PRD

📄 版本：v1.1 ✏️ 作者：Laura 📅 更新日期：2026-10-07

一、需求概述

推广渠道管理模块现有四种埋点类型（常规推广、Facebook API、TK API、Kwai API），均面向在外部广告平台投放的 H5 渠道链接。本需求新增三种面向独立安装包的埋点类型：APK上架包（商户自行封装并上架谷歌商店的马甲包，SD=6）、IOS上架包（商户自行封装并上架苹果商店的安装包，SD=4）、APK（平台自有的 H5 套壳包，打包指定 URL 后由商户自行分发）。

1.1 链路与适用设备

三种新埋点的本质差异在于：渠道链接不对外投放，而是打包进对应的安装包中使用。用户先安装 App，App 启动后在内置 WebView 中加载该渠道链接并落地至配置的页面。因此每种埋点的渠道链接只会在固定类型的设备上被访问，无需考虑跨设备访问的交互。

埋点类型链接打包载体适用设备用户获取路径
APK上架包商户封装的谷歌商店马甲包安卓设备在谷歌商店按名称搜索到该包并安装，启动后在 App 内加载渠道链接
IOS上架包商户封装的苹果商店安装包iOS 设备在苹果商店搜索到该包并安装，启动后在 App 内加载渠道链接
APK平台自有的 H5 套壳包安卓设备由商户自行分发安装包，不经应用商店，安装后在 App 内加载打包的渠道链接

1.2 需求边界

后台不对落地指向、跳转域名、渠道设置等任何字段做限制或联动置灰，三种新埋点下所有字段与现有埋点保持一致，均可正常配置与保存。

实际业务中，运营仅会按既定规则为三种新埋点配置特定的落地指向，且每种埋点的渠道链接只会在固定类型的设备上被访问。因此本需求仅就「特定落地指向 + 对应设备」的组合描述主流程（见第三、四章）——这是对需求描述范围的界定，不构成对后台配置的约束。其余落地指向与设备组合在实际业务中不会产生，本需求不对其做交互定义。

二、后台配置

2.1 埋点类型新增选项

「埋点类型」为渠道的必填字段，下拉单选，决定该渠道的数据追踪方式与前台落地行为。本需求在现有选项基础上新增以下三项，新增选项排列于现有四项之后。

新增选项展开字段事件说明选项说明
APK上架包 全渠道回传kwai ID 非必填，见 2.2 ✅ 有见 2.3 商户自行封装并上架谷歌商店的马甲包，SD=6。渠道链接打包进该上架包，由安卓用户在 App 内访问。
IOS上架包 无 ✅ 有见 2.3 商户自行封装并上架苹果商店的安装包，SD=4。渠道链接打包进该上架包，由 iOS 用户在 App 内访问。
APK 无 ❌ 无 平台自有的 H5 套壳包，打包指定 URL 生成安装包，由商户自行分发，不经应用商店，由安卓用户在 App 内访问。
三种新埋点均不需要填写 Pixel ID 与访问令牌 TOKEN，不涉及 test_event_code 事件测试字段。

2.3 事件说明

事件说明用于展示该埋点类型的回传事件清单，内容格式为「中文事件名称 - 事件标识符」。两种上架包埋点由客户端按我方统一埋点规范上报，事件清单由客户端埋点文档定义（见下方「回传事件清单」），不依赖三方平台文档。入口有两处，均仅对 APK上架包与 IOS上架包展示：

入口位置展示条件交互说明
渠道表单内 新增渠道 / 编辑渠道 / 批量新增渠道弹窗中，「埋点类型」选择 APK上架包 或 IOS上架包 后展示；选择 APK 或其他埋点类型时不展示 在埋点类型字段下方展示事件说明入口，供运营在配置渠道时直接查看该类型的回传事件清单。
渠道列表操作列 渠道埋点类型为 APK上架包 或 IOS上架包 时展示「说明」按钮；埋点类型为 APK 时不展示 点击弹出事件说明弹窗，标题为该埋点类型名称，内容为回传事件列表，与表单内展示的内容一致。

APK 类型不涉及回传事件，表单内与渠道列表操作列两处入口均不展示。

2.4 测试回传弹窗

点击渠道列表操作列「Test」按钮后弹出，用于测试该渠道的埋点回传是否正常。三种新埋点下弹窗字段表现如下：

字段三种新埋点下表现说明
渠道名称只读回填自动填入当前渠道名称。
类型只读回填自动填入当前渠道的埋点类型，即 APK上架包 / IOS上架包 / APK。
Pixel Id保留字段，空值置灰三种新埋点无 Pixel ID 概念，该字段保留展示但内容为空且不可编辑，以维持弹窗布局与现有埋点一致。
测试链接可编辑用于测试回传的链接，测试成功后应使用渠道链接进行投放。

2.5 影响范围

三个新增埋点选项需在以下位置同步生效，选项顺序与文案保持一致：渠道列表筛选区的「埋点类型」下拉（含「全部」选项）、新增渠道弹窗、编辑渠道弹窗、批量新增渠道弹窗（三者渠道设置字段一致）、渠道列表数据表格的「埋点类型」列展示、测试回传弹窗的「类型」只读字段，以及推广效果报表的埋点类型维度。现有四种埋点类型的字段展开、事件说明与前台行为不受本需求影响。

四、前台交互主流程

4.1 APK上架包 · 安卓设备

用户从谷歌商店安装马甲包并启动后的完整流程如下。

① 用户在谷歌商店按名称搜索并安装 APK上架包
↓
② 启动 App，App 内加载该渠道链接，经跳转域名落地至官网首页 / 官网注册页
↓
③ 落地页不展示顶部固定横幅与底部安装浮层
↓
④ 按渠道「引导安装」配置的弹框内容、弹框时间点与弹框间隔时间，弹出安装引导弹窗
↓
⑤ 用户点击安装，按弹框安装类型下载并安装 PWA 或 APK
↓
⑥ 打开新安装的 PWA / APK，自动登录，见第五章

交互要点

交互项是否生效说明
域名跳转 ✅ 生效 按渠道所配置的跳转域名正常落地至官网首页 / 官网注册页。
下载按钮
顶部横幅 + 底部浮层		 ❌ 不展示 用户已处于 App 环境内，无需再以横幅与浮层引导下载，后台「下载按钮」开关的配置不作用于该类渠道。
引导安装 ✅ 生效 按后台安卓 Tab 配置的弹框内容、弹框时间点、弹框间隔时间正常弹出；弹窗关闭逻辑与《安装引导模块 PRD》口径一致。

4.2 IOS上架包 · iOS 设备

用户从苹果商店安装后启动 App，App 内加载渠道链接并经跳转域名落地至官网首页 / 官网注册页，域名跳转正常生效。落地页不展示顶部固定横幅与底部安装浮层，也不弹出安装引导弹窗——用户已通过苹果商店完成安装，App 内无需再做任何安装引导。用户落地后直接进入正常的注册、登录与游戏流程。

后台「渠道设置」苹果 Tab 的下载按钮与引导安装字段仍可正常配置与保存，但不作用于该类渠道的前台表现。

4.3 APK · 安卓设备

用户安装商户分发的 H5 套壳包并启动，App 内加载打包的渠道链接并落地至官网首页，域名跳转正常生效。落地页不展示顶部固定横幅与底部安装浮层，也不弹出安装引导弹窗——套壳包本身即为 App 形态，无需再引导安装。用户落地后直接进入正常的注册、登录与游戏流程。

后台「渠道设置」安卓 Tab 的下载按钮与引导安装字段仍可正常配置与保存，但不作用于该类渠道的前台表现。

五、自动登录（登录态承接）

适用范围：仅 APK上架包渠道。用户在 App 内的 H5 落地页通过安装引导安装 PWA 或 APK 后，打开新安装的客户端应直接进入已登录状态，无需再次输入账号密码。

场景目标表现说明
用户在 H5 已登录后安装 自动登录 打开新安装的 PWA / APK 时自动承接 H5 侧的登录态，直接进入已登录的首页，不展示登录页，不要求重新输入账密。
用户在 H5 未登录时安装 保持未登录 无登录态可承接，打开客户端后为未登录状态，用户自行登录或注册。本需求不对未登录场景做额外承接。
PWA 与 APK 的覆盖 两者均需支持 弹框安装类型为 pwa(快速安装)、apk(需要自己封装)、pwa(优先)+apk(推荐使用) 时，最终安装的客户端均需实现自动登录。
本自动登录与《推广渠道管理模块 PRD》3.5.3 节「已安装唤起」（用户点击安装入口时先尝试唤起已安装的 PWA / APK，命中则直接打开并保持登录态无缝进入）属于同一套登录态传递机制，实现与口径直接引用该节，本文不重复描述；对应的安装引导侧说明见《安装引导模块 PRD》2.3 节。差异仅在于触发时机：「已安装唤起」作用于用户点击安装、客户端已存在的场景；本节作用于用户首次完成安装、首次打开新客户端的场景。

六、验收要点

  1. 埋点类型字段：筛选区、新增 / 编辑 / 批量新增渠道弹窗的「埋点类型」下拉均展示 APK上架包、IOS上架包、APK 三个新选项，文案与顺序一致；渠道列表「埋点类型」列与测试回传弹窗「类型」字段可正确展示三种新类型。
  2. 专属字段：选择 APK上架包 展开「全渠道回传kwai ID」且为非必填；切换至其他埋点类型时该字段隐藏并清空；IOS上架包与 APK 不展开任何子字段。
  3. 事件说明：表单内选择 APK上架包 或 IOS上架包 后展示事件说明，内容为 9 项回传事件、顺序与 2.3 清单一致、事件标识符大小写正确；渠道列表操作列对这两类渠道展示「说明」按钮，弹窗标题为埋点类型名称、内容与表单内一致；APK 两处均不展示。
  4. 测试回传弹窗：三种新埋点下 Pixel Id 字段保留展示、内容为空且置灰不可编辑，渠道名称与类型正确只读回填。
  5. APK上架包主流程：安卓设备从谷歌商店安装并启动后，可正常落地至官网首页 / 官网注册页；不展示顶部横幅与底部安装浮层；安装引导弹窗按配置的弹框时间点与间隔正常弹出；弹框安装类型三种配置下均可正确安装；非 Chrome 浏览器点击安装可正常唤起 Chrome。
  6. 自动登录：在 H5 已登录状态下通过安装引导安装 PWA 或 APK，打开新安装的客户端直接为已登录状态；未登录状态下安装，打开后为未登录状态。
  7. IOS上架包主流程：iOS 设备从苹果商店安装并启动后，可正常落地至官网首页 / 官网注册页；不展示顶部横幅与底部安装浮层，不弹出安装引导弹窗。
  8. APK 主流程：安卓设备安装套壳包并启动后，可正常落地至官网首页；不展示顶部横幅与底部安装浮层，不弹出安装引导弹窗。
  9. 回归：常规推广、Facebook API、TK API、Kwai API 四种现有埋点的字段展开、事件说明、测试回传弹窗与前台下载按钮 / 安装引导行为均不受影响。
