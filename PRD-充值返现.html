一、需求背景与范围

平台希望以存款方式为维度做差异化激励：对成本较低、到账更稳定的渠道给予更高的充值返现比例，把会员的充值行为向这些渠道引导；对成本较高的渠道则不给或少给返现。此前「赠送比例」这一取值只散落在各渠道需求中被引用，缺少统一的配置入口与统一的发放、上限、稽核口径。

本需求在商户后台新增「商户财务配置 — 充值返现设置」页面，把平台已接入的全部存款方式集中在一张列表中，按存款方式逐一配置返现百分比、每日最高优惠、提现稽核倍数与启用状态；并定义返现在充值成功后的计算、封顶、入账与账变规则。配置保存后，前台充值页即按该配置展示赠送角标与「含赠送」副行，会员充值成功后由系统自动发放返现。

二、名词定义

名词定义
充值返现会员通过指定存款方式完成充值后，平台按配置比例额外赠送的金额。后台功能名为「充值返现」，前台对会员呈现为「含赠送」。
存款方式平台已接入的支付渠道，即列表的行维度。当前共 8 条：bestpay、u2cpay、虚拟币、newgpay、ydpay、银联、ECNY、OKPay。
返现方式返现金额的计算形式。本期仅支持「比例金额」一种，即按充值金额的百分比计算，列表中为只读展示，不提供切换。
返现百分比（%）该存款方式的返现比例，支持 3 位小数。返现金额 ＝ 实际到账充值金额 × 返现百分比。
每日最高优惠单个会员在同一存款方式下、单个自然日内可获得的返现金额上限，单位为平台币种。
提现稽核倍数返现金额在会员提现前需完成的有效投注倍数。追加有效投注要求 ＝ 本次返现金额 × 稽核倍数。
自然日统一按平台运营时区 UTC-3（巴西雷西亚尔）计算，每日 00:00:00 起算、23:59:59 结束。后台列表与筛选区的时间均为 UTC-3。
实际到账充值金额充值订单经三方支付成功回调后，真正计入会员账户的本金金额，不含三方手续费。

四、后台功能：充值返现设置

4.1 菜单位置与页面构成

  • 菜单位置：商户后台左侧导航「商户财务配置」→「充值返现设置」，位于「支付方式管理」之下、「代付商户管理」之上。
  • 页面构成：自上而下为筛选区、时区提示、配置列表、分页条；列表「操作」列的「编辑」按钮唤起「会员存款返现设置」弹窗。
  • 数据来源：列表展示平台已接入的全部存款方式，由支付方式管理同步，不提供新增与删除；新接入的存款方式自动追加一行，返现百分比与每日最高优惠初始为 0，状态默认关闭。
  • 默认排序：按最近操作时间倒序，从未配置过的存款方式排在末尾。

4.2 筛选区字段说明

字段控件必填说明与选项
最后操作时间日期范围选择器否起止两个输入框，按最近一次保存或开关切换的时间筛选。时间口径为 UTC-3，筛选区下方以红色提示文案「当前时间为 UTC-3 时区」常驻说明。起止均为空时不参与筛选；仅填其一时，另一端视为不限。
存款方式下拉单选否选项为列表中已接入的全部存款方式，与列表行一一对应；默认空（全部）。
操作人文本输入否按最近操作人账号模糊匹配；从未配置过、操作人为空的行不会被该条件命中。
查 询主按钮—按当前筛选条件重新拉取列表，结果回到第 1 页。
重 置次按钮—清空全部筛选条件并重新拉取全量列表。

4.3 列表字段说明

列是否可编辑说明与取值
存款方式只读支付渠道名称，与支付方式管理中的配置同名，如 bestpay、u2cpay、虚拟币、newgpay、ydpay、银联、ECNY、OKPay。
返现方式只读固定展示「比例金额」。本期仅支持按比例计算，不提供固定金额等其他方式，亦不提供切换控件。
返现百分比例（%）弹窗内编辑展示当前配置的返现比例，去除末尾无意义的 0 后展示（如配置 1.000 展示为 1、0.200 展示为 0.2、2.500 展示为 2.5）。展示为 0 表示该存款方式尚未配置过返现。
每日最高优惠（元）弹窗内编辑展示当前配置的单日封顶金额，去除末尾无意义的 0 后展示。展示为 0 表示尚未配置。
状态行内可切换开关控件，开启＝该存款方式的返现规则生效，关闭＝不生效。详见 4.4。
最近操作时间只读该行最后一次保存配置或切换状态的时间，格式 YYYY-MM-DD HH:mm:ss (UTC-3)。从未操作过时展示为空。
操作人只读最近一次操作的后台账号。从未操作过时展示为空。
操作—「编辑」按钮，点击唤起「会员存款返现设置」弹窗（4.5）。
  • 分页：底部展示「共 N 条数据」与页码，每页条数下拉默认 50 条 / 页。
  • 列工具：沿用现有后台列表的右上角工具组（刷新 / 密度 / 列设置），行为与其他列表页一致。

4.4 状态开关

  • 切换方式：在列表行内直接点击开关即生效，不弹二次确认，成功后轻提示「操作成功」并刷新该行的最近操作时间与操作人。
  • 与配置值相互独立：开关可自由切换，不受返现百分比与每日最高优惠取值的约束。即允许「开关开启但返现百分比为 0」的组合存在。
  • 生效判定：返现是否发放，取决于「状态开启」与「返现百分比 > 0」同时成立。开关开启但返现百分比为 0 时，视同无返现：不计算、不发放、不产生账变，前台亦不展示赠送角标与「含赠送」副行（见第六章）。
  • 关闭的影响范围：关闭仅对关闭之后产生的充值订单生效，已发放的返现不回收、已追加的提现流水要求不撤销。

4.5 编辑弹窗：会员存款返现设置

点击列表行「编辑」唤起弹窗，标题为「会员存款返现设置」，分「基本信息」与「返现设置」两组，底部为「保存」「重置」。

基本信息

字段控件必填说明与选项
存款方式纯文本—只读展示当前编辑行的存款方式名称，不可修改，用于确认操作对象。

返现设置

字段控件必填说明与选项
* 返现百分比（%）数字输入是该存款方式的返现比例。输入区间 0.001 ~ 100.000，最多 3 位小数，保存时统一补齐为 3 位小数存储（如输入 1 存为 1.000）。该值直接决定前台渠道角标的「+N%」与结算栏「含赠送」金额。
* 每日最高优惠数字输入是单个会员在该存款方式下单个自然日（UTC-3）可获得的返现金额上限。输入区间 0.01 ~ 1000000.00，最多 2 位小数，保存时统一补齐为 2 位小数存储。该值同时作为前台奖励规则气泡中「每日最高奖励」的取值来源。
提现稽核倍数数字输入否返现金额需完成的有效投注倍数。输入为大于等于 1 的整数，不接受小数与 0。不填时默认为 0，表示该笔赠送金额不参与提现流水稽核计算。该值同时作为前台奖励规则气泡中「提现流水要求」的倍数取值来源。
保 存主按钮—通过校验后提交，弹窗关闭，轻提示「保存成功」，列表对应行的配置值、最近操作时间、操作人同步刷新。
重 置次按钮—将三项输入还原为本次打开弹窗时的已保存值（非清空），弹窗保持打开。

4.6 字段校验与温馨提示

弹窗内「返现设置」下方以红色文案常驻展示以下 5 条温馨提示，内容与校验规则一一对应：

序提示文案对应校验与拦截
1「返现百分比（%）」与「每日最高优惠」为必填项，必须同时填写两项不允许只填其一。任一为空时点击保存，在空值字段下方标红提示「请填写{字段名}」，不提交。
2「返现百分比（%）」的输入区间「0.001 ~ 100.000」小于 0.001、大于 100.000 或超过 3 位小数时标红拦截，提示「返现百分比的输入区间为 0.001 ~ 100.000」。不接受 0——若需停用该存款方式的返现，使用列表状态开关关闭。
3「每日最高优惠」的输入区间「0.01 ~ 1000000.00」小于 0.01、大于 1000000.00 或超过 2 位小数时标红拦截，提示「每日最高优惠的输入区间为 0.01 ~ 1000000.00」。
4「提现稽核倍数」非必填，不填时默认显示为 0，加赠金额部分不参与提现流水稽核计算允许留空；留空保存后，列表与下次打开弹窗均显示为 0，发放时不追加有效投注要求。
5「提现稽核倍数」的输入为大于等于 1 的整数填入 0、负数、小数或非数字时标红拦截，提示「提现稽核倍数需为大于等于 1 的整数」。

输入态约束：三项均只允许输入数字与小数点，粘贴含非法字符的内容时自动过滤；超出小数位数时在失焦后按规则截断并标红提示，不静默修改为合法值。

4.7 配置生效范围与操作留痕

  • 即时生效，仅对新订单：保存成功后配置立即生效。某笔充值返现以多少计算，以该订单支付成功回调时服务端读取到的配置为准；修改前已完成的订单不补发、不追回，已追加的提现流水要求也不随配置变更而调整。
  • 页面停留期间的配置变更：会员在前台充值页停留期间若后台修改了配置，前台展示的赠送金额可能与实际入账不一致；一律以服务端结果为准，刷新后的余额即为准确值。
  • 每日上限的跨配置累计：当日已发放的返现累计值 S 不因配置修改而清零，仍按自然日累计，于次日 00:00:00（UTC-3）统一重置。若新上限低于当日已累计值，当日剩余额度视为 0，不发放亦不追回。
  • 操作留痕：每次保存配置或切换状态，均记录操作时间（UTC-3）与操作人账号，并在列表「最近操作时间」「操作人」两列展示；完整的变更前后值进入后台操作日志，可按账号与时间追溯。

五、返现计算与发放规则

5.1 计算基数与取整

返现金额（计算值）＝ 向下取 2 位小数（ 实际到账充值金额 × 返现百分比 ÷ 100 ）
  • 计算基数：取实际到账的本金金额，即三方支付成功回调后真正计入会员账户的金额，不含三方手续费。若实际到账金额与会员提交金额因三方扣费而不一致，以实际到账金额为准。
  • 取整规则：计算结果一律向下取整至 2 位小数（舍去第 3 位及以后，不四舍五入），平台不向上多给。例：到账 R$ 33,33、比例 1% → 0,3333 → 实发 R$ 0,33。
  • 触发时点：仅在充值订单支付成功时触发一次。订单失败、超时失效、关闭或被撤销的，均不触发返现；订单后续被人工冲正的，对应返现随之冲回并生成反向账变。
  • 零值处理：计算值取整后为 0.00 时，不入账、不产生账变，前台亦不展示返现提示。

5.2 每日最高优惠的统计口径

  • 统计维度：会员 × 存款方式 × 自然日。每种存款方式各自独立累计当日返现总额，互不影响、互不共用额度。例：会员当日通过 bestpay 已拿满 R$ 8,00 上限后，仍可继续通过 newgpay 获得该渠道上限内的返现。
  • 重置时点：按 UTC-3 自然日，每日 00:00:00 起累计值归零。跨日时点以充值订单支付成功回调的时间归属当日，而非订单创建时间。
  • 封顶计算：
当日剩余额度 R ＝ 每日最高优惠 − 当日该存款方式已发放返现累计 S
本次实发金额 ＝ 取较小值（ 返现金额计算值 ，R ）
若 R ≤ 0，本次实发金额 ＝ 0，不入账、不产生账变
场景配置当日已累计 S本笔计算值实发结果
未触顶比例 1%，上限 8,00R$ 0,00R$ 3,00实发 R$ 3,00，S 更新为 3,00。
部分截断比例 1%，上限 8,00R$ 6,50R$ 3,00剩余额度 1,50 < 3,00，实发 R$ 1,50，S 更新为 8,00。
额度用尽比例 1%，上限 8,00R$ 8,00R$ 3,00剩余额度为 0，不发放、不产生账变，本金正常入账。
跨渠道独立bestpay 上限 8,00

newgpay 已 0,00		newgpay 本笔 2,50两渠道额度独立，newgpay 实发 R$ 2,50。

5.3 提现稽核倍数

追加有效投注要求 ＝ 本次实发返现金额 × 提现稽核倍数
  • 稽核范围：稽核对象仅为赠送部分，即本次实发的返现金额，不含充值本金。本金自身的提现流水要求沿用平台既有的存款稽核规则，两者各自独立计算后合并计入会员的待完成有效投注。
  • 倍数为 0 或未填：该笔返现不追加任何有效投注要求，入账后与普通余额无差别，可直接参与提现。
  • 多笔叠加：会员同日多次充值产生的多笔返现，各自按发放当时的倍数独立计算追加额，累加进待完成有效投注；某笔配置修改不影响此前已生成的追加额。
  • 前台可查：倍数取值通过充值页「含赠送」旁的奖励规则气泡向会员前置披露，表述为「赠送金额 ×{倍数}」，见第六章。

5.4 入账与账变类型

  • 入账账户：返现金额在充值成功后由系统自动即时入账至会员可用余额，与充值本金进入同一账户，无需会员手动领取，不设待领取状态、不设过期作废。
  • 入账顺序：先完成本金入账，再执行返现入账，两者为两条独立的账变记录，便于对账与客诉核查。

新增账变类型

本功能产生的返现入账需要新增账变类型承载，在现有一类账变「活动优惠」之下新增二类账变「充值赠送」：

层级名称增减方向说明
一类账变活动优惠加款沿用现有，不新增、不改名。
二类账变充值赠送（新增）加款专用于承载充值返现的入账记录。本功能产生的全部返现只记入该二类账变，不与充值活动档位奖励、神秘彩金、会员答谢等其他「活动优惠」下的二类账变混记。
  • 适用范围：该二类账变适用于全部存款方式的充值返现，不按渠道再拆分；渠道信息通过账变记录关联的充值订单号追溯。
  • 生效位置：新增后需同步出现在会员账变查询、报表查询的账变类型筛选项与前台会员账变 / 交易记录中，口径与其他二类账变一致。
  • 冲正：充值订单被人工冲正时，对应返现生成同类型的反向（减款）账变，并同步扣减当日累计值 S 与已追加的有效投注要求。

六、前台联动：充值页呈现

前台充值页的呈现方式沿用现有已确认的结构与文案，本需求不做改动，仅明确各处取值与后台配置项的对应关系。页面结构、样式与交互见《存款页优化说明（PIX / NewGPay）》。

前台元素取值来源联动规则
渠道按钮右上角赠送角标该存款方式的返现百分比内容为「+N%」，N 取后台配置值（去除末尾无意义的 0）。仅在存款页展示，取款页不展示。
结算栏「含赠送」副行返现百分比 × 当前输入金额实时计算并展示「+R$ X,XX」，取整规则与 5.1 一致。该行为预估值，不扣减每日剩余额度——实际入账以服务端结果为准。
「您将收到」主行输入金额 ×（1 ＋ 返现百分比）保留 2 位小数；输入为空或 0 时不展示数值。
奖励规则气泡 —
每日最高奖励		该存款方式的每日最高优惠展示为「每日最高奖励　R$ {配置值}」，取后台配置的原始值，不随当日已用额度变化。
奖励规则气泡 —
提现流水要求		该存款方式的提现稽核倍数展示为「提现流水要求　赠送金额 ×{配置倍数}」。倍数为 0 时该行不展示，气泡仅保留「每日最高奖励」一行。

无返现时的降级表现：当该存款方式状态关闭或返现百分比为 0 时，前台视同无返现——渠道按钮不显示赠送角标，结算栏不渲染「含赠送」副行（问号图标随之不出现），结算栏仅保留「您将收到」一行、高度随之收缩。

八、边界与异常处理

场景处理方式
存款方式从未配置过返现列表返现百分比与每日最高优惠展示为 0，状态为关闭，最近操作时间与操作人为空。前台不展示角标与「含赠送」副行。
状态开启但返现百分比为 0允许保存该状态组合，但视同无返现：不计算、不发放、不产生账变，前台不展示角标与「含赠送」副行。
计算值取整后为 0.00不入账、不产生账变、不扣减当日额度；本金正常入账，前台不提示返现。
当日该存款方式额度已用尽本金正常入账，返现不发放、不产生账变。前台结算栏在输入阶段仍按比例展示预估赠送（不做额度预检），实际以服务端结果为准。
剩余额度小于本笔计算值按剩余额度部分发放，实发金额记入账变；提现流水追加额按实发金额（而非计算值）× 倍数计算。
会员停留页面期间配置被修改以提交时服务端读取到的配置为准。若与前台展示的「含赠送」金额不一致，按服务端结果入账，刷新后的余额即为准确值。
每日最高优惠被下调至低于当日已累计值当日剩余额度视为 0，本日不再发放；已发放部分不追回，次日按新上限重新累计。
提现稽核倍数被修改仅对修改后新产生的返现生效；此前已追加的有效投注要求不随之调整。
充值订单支付失败 / 超时失效 / 关闭不触发返现计算，不产生账变，不占用当日额度。
充值订单被人工冲正对应返现生成反向（减款）账变，同步回退当日累计值 S 与已追加的有效投注要求。若会员余额不足以扣回，按平台既有的负余额处理规则执行。
同一订单回调重复到达按充值订单号做幂等处理，同一订单最多产生一笔「充值赠送」账变，重复回调直接忽略。
跨日时点充值（临近 00:00 UTC-3）以支付成功回调时间归属自然日。订单创建于前一日、回调发生在次日的，计入次日额度。
新接入存款方式列表自动追加一行，配置值为 0、状态关闭；在后台完成配置并开启前，该渠道不产生返现。
存款方式在支付方式管理中被下线列表保留该行并置为不可编辑（「编辑」按钮置灰、状态开关置灰），历史配置与账变记录保留可查。
保存并发冲突两名管理员同时编辑同一行时，后提交者覆盖，并在操作日志中各记一条；提交后列表刷新为最新值。

九、权限

  • 菜单权限：「商户财务配置 — 充值返现设置」作为独立权限点纳入后台角色权限树，未授权账号不展示该菜单项。
  • 操作权限：拆分为查看与编辑两级。仅具备查看权限时，列表正常展示，「编辑」按钮与状态开关置灰不可操作。
  • 生效范围：配置以商户为单位隔离，一个商户的配置不影响其他商户。
  • 审计：全部保存与状态切换行为进入后台操作日志，记录操作账号、时间（UTC-3）、存款方式与变更前后取值。

十、关联需求同步说明

关联文档同步点
《新增 NewGPay 支付渠道 PRD》该文档第四章将 NEWGPAY 的「赠送比例」列为待补充的后台配置项。本 PRD 即为其配置入口：NEWGPAY 的赠送比例取自本页「充值返现设置」中 newgpay 一行的返现百分比，不另设渠道级配置；该文档 5.4「赠送比例与实际到账」的计算口径以本 PRD 第五章为准（新增了每日最高优惠封顶与向下取 2 位小数两项约束）。
《存款页优化说明（PIX / NewGPay）》该文档 3.4「奖励规则提示」气泡中的每日最高奖励与提现流水要求，取值分别对应本页的每日最高优惠与提现稽核倍数；前台展示结构与中葡文案以该文档为准，本 PRD 不作改动。
《BESTPAY 收银页站内化 PRD》BESTPAY 渠道的赠送比例取自本页 bestpay 一行的返现百分比。收银页本身不展示返现信息，返现在支付成功回调后按本 PRD 第五章发放。
《充值活动 PRD》充值活动的档位奖励与本功能的充值返现为两套独立奖励，可同时发放：前者手动领取、记入其自身的账变类型；后者自动入账、记入新增的二类账变「充值赠送」。两者的提现稽核要求各自独立计算后累加。
支付方式管理本页列表的行来源于支付方式管理中已接入的存款方式，新增与下线由该模块驱动，本页不提供新增 / 删除入口。
