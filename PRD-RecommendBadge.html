一、需求背景与范围

前台存款页、取款页的渠道按钮右上角目前有两类角标：限时充值返利活动按「生效存款方式」配置的自定义角标文案，以及充提返现按返现百分比生成的「+N%」角标。两者都依附于营销活动或返现配置，运营无法在没有优惠的情况下单独突出某个渠道（如成功率高、到账快、成本低的渠道）。

本需求在「商户财务配置 — 支付方式管理」（存款方式）与「商户财务配置 — 提现管理 — 提现通道配置」（提现通道）中新增「是否推荐」开关与「角标文案」，字段规则对齐限时充值返利的「推荐 / 角标文案」。前台同一渠道按钮的角标位只显示一个角标，三类角标互斥，优先级为：限时充值返利角标 ＞ 充提返现角标 ＞ 推荐角标。

本次需求范围

模块范围对应章节
支付方式管理列表新增「推荐」「角标文案」两列；添加 / 修改弹窗新增「是否推荐」开关与「角标文案」输入框。4.1、4.2、4.5
提现管理 — 提现通道配置列表新增「推荐」「角标文案」两列；编辑弹窗新增「是否推荐」开关与「角标文案」输入框。4.3、4.4、4.5
前台渠道角标存款页、取款页渠道按钮右上角新增推荐角标，并定义与限时充值返利角标、充提返现角标的互斥与顺延规则；快捷档位角标跟随渠道角标类型显示，推荐角标不出现在快捷档位上。第五章

不在本需求范围：限时充值返利活动的「生效存款方式」配置及其角标展示条件，沿用活动现有逻辑，本需求不改动；充值返现、提款返现的配置与计算规则见《充值返现 PRD》《提款返现 PRD》，本需求只调整其渠道角标与快捷档位角标在互斥时的显示（见 5.2 ~ 5.4）；渠道按钮的排序不受「是否推荐」影响，仍按「支付方式排序」「通道排序」及提现通道「排序」现有规则；「提现管理 — 提款方式配置」（CPF / PHONE 收款键类型）不涉及推荐角标。

二、名词定义

名词定义
存款方式「支付方式管理」中的一行配置（支付方式 / 存款方式，如 bestpay / pix_bestpay），对应前台存款页的一个渠道按钮。本需求的充值侧推荐配置以存款方式为维度。
提现通道「提现管理 — 提现通道配置」中的一行配置（如 pix、NewGPay、u2cpay），对应前台取款页的一个渠道按钮。本需求的提款侧推荐配置以提现通道为维度。
渠道角标位存款页、取款页渠道按钮右上角的角标位置。同一渠道按钮同一时刻最多显示 1 个角标。
限时充值返利角标限时充值返利活动「生效存款方式」中「推荐」为是的存款方式，按活动配置的「角标文案」显示的角标。仅出现在存款页。
充提返现角标存款页的充值返现角标与取款页的提款返现角标的统称，内容为「+N%」，N 取对应存款方式 / 提现通道的返现百分比，规则见《充值返现 PRD》第六章与《提款返现 PRD》6.1 节。
推荐角标本需求新增。存款方式或提现通道「是否推荐」开启后，按其「角标文案」显示的角标。
提现文案（区分）「提现通道配置」现有字段，前台取款页的渠道提示文案，最多 50 字，与推荐角标无关。本需求的「角标文案」为独立的新字段。

三、交互逻辑流程图

说明：每个渠道按钮独立判定，自上而下取第一个成立的角标，命中后不再判断后续条件。「限时充值返利角标展示条件」沿用该活动现有逻辑；「充值返现 / 提款返现生效」指对应存款方式 / 提现通道已在「充提返现设置」中添加且状态开启；「推荐开启」指「是否推荐」为开启（开启时角标文案必填，见 4.5）。取款页不涉及限时充值返利。

四、后台配置

4.1 支付方式管理：列表字段

菜单：商户财务配置 → 支付方式管理。筛选区、「添加」按钮、分页与现有列不变，在「状态」列之后新增两列：

列显示规则
序号 / 支付方式/存款方式 / 状态现有，不变。
推荐新增「是否推荐」开启显示「是」，关闭显示「否」。
角标文案新增「是否推荐」开启时显示该存款方式的角标文案原文；关闭时显示「-」。
备注说明 / 创建/更新时间 / 操作现有，不变。保存推荐配置同样刷新「更新时间」。

4.2 支付方式管理：添加 / 修改弹窗

添加与修改共用同一弹窗。在「是否启用」之下、「备注」之上新增两行，其余字段与「取消 / 确认」按钮不变：

序字段说明
1* 支付方式现有，不变（修改时置灰不可改）。
2* 存款方式现有，不变（红字提示「作为客户端用户存款方式显示，请谨填写！」）。
3是否启用现有，不变。
4是否推荐新增见 4.5。
5角标文案新增见 4.5。
6备注现有，不变（最多 115 字）。

「是否启用」与「是否推荐」相互独立：存款方式禁用时可保留推荐配置，前台因该存款方式不展示而不显示角标；重新启用后按保留的配置显示。

4.3 提现管理 — 提现通道配置：列表字段

菜单：商户财务配置 → 提现管理 → 「提现通道配置」标签页。在「快捷金额」列之后新增两列，其余列与操作按钮（编辑 / 启用或禁用 / 排序）不变：

列显示规则
排序 / 提现方式 / 状态 / 提现文案 / 快捷金额现有，不变。
推荐新增「是否推荐」开启显示「是」，关闭显示「否」。
角标文案新增「是否推荐」开启时显示该提现通道的角标文案原文；关闭时显示「-」。
最后操作时间 / 操作人 / 操作现有，不变。保存推荐配置同样刷新「最后操作时间」与「操作人」。

4.4 提现管理 — 提现通道配置：编辑弹窗

点击行内「编辑」打开。在现有「快捷金额」「编辑文案」之下新增两行，「取消 / 确认」按钮不变：

序字段说明
1快捷金额现有，不变（逗号分隔，最多 999 个）。
2编辑文案现有，不变（最多 50 字，对应列表「提现文案」）。
3是否推荐新增见 4.5。
4角标文案新增见 4.5。

提现通道的启用 / 禁用仍通过列表操作列切换，与「是否推荐」相互独立，规则同 4.2 末段。

4.5 「是否推荐」与「角标文案」字段规格

两个弹窗中的新增字段规格一致，均对齐限时充值返利「生效存款方式」中的「推荐 / 角标文案」：

字段含义控件必填输入要求与联动前台效果
是否推荐是否在前台为该存款方式 / 提现通道显示推荐角标。开关（是 / 否）否（始终有值）默认「否」。
由「否」切到「是」：「角标文案」变为可输入，标签前出现必填星标，占位提示变为「请输入角标文案」。
由「是」切到「否」：「角标文案」清空并置灰（不可输入），占位提示变为「开启推荐后填写」，必填星标消失，已显示的校验错误同时清除。		开启且未被更高优先级角标占用时，渠道按钮右上角显示推荐角标，见第五章。
角标文案推荐角标的显示内容。单行文本框，右侧显示字数计数「已输入/8」「是否推荐」开启时必填；关闭时不可填最多 8 个字符，达到 8 个后不可继续输入（粘贴超长内容时截取前 8 个）；汉字、字母、数字、符号、空格均按 1 个字符计。
不限制字符类型，不做多语言区分，前台原样展示。
保存时自动去除首尾空格；去除后为空视为未填写。
弹窗打开时回填已保存的文案。		推荐角标显示该文案原文。

校验与错误提示

场景处理
「是否推荐」开启，角标文案为空或仅含空格，点击「确认」拦截保存，文本框标红，下方显示「请输入角标文案」，弹窗保持打开；其他字段校验照常执行，错误同时展示。
标红后重新输入输入非空内容时立即清除标红与错误提示。
「是否推荐」关闭，点击「确认」角标文案不参与校验，按空值保存。

4.6 配置生效与操作留痕

  • 生效时点：保存成功后立即生效，前台在 5.5 所列读取时机按新配置显示。
  • 上线初始值：全部存款方式与提现通道的「是否推荐」初始为「否」、角标文案为空，前台不出现推荐角标，直至运营手动开启。
  • 数量不限：不限制同时开启推荐的存款方式或提现通道数量。
  • 配置隔离：以商户为单位隔离，与所属页面现有配置一致。
  • 操作日志：「是否推荐」「角标文案」的变更计入后台操作日志，记录操作账号、时间（UTC-3）、所属页面、存款方式 / 提现通道名称及变更前后取值。

五、前台显示逻辑

5.1 角标位置与形态

项要求
位置存款页、取款页渠道区每个渠道按钮的右上角，即现有限时充值返利角标与充提返现角标的同一位置。
内容该存款方式 / 提现通道的「角标文案」原文，单行展示，不换行、不截断（已由 8 字符上限保证）。
样式以 UI 设计稿为准。三类角标共用同一角标位，可按类型区分样式。
语言角标文案不随客户端语言切换，各语言下均显示同一文案；运营应按目标市场语言填写。
交互角标仅作展示，不可点击；点击区域与渠道按钮一致，不改变渠道选中逻辑。

5.2 存款页：角标优先级

每个存款方式的渠道按钮按下表自上而下判定，取第一个成立的角标显示，最多显示 1 个；高优先级角标实际不显示时，顺延判定下一级。

优先级角标显示条件内容
1限时充值返利角标当前会员满足限时充值返利的角标展示条件，且该存款方式在活动「生效存款方式」中「推荐」为是。展示条件与撤下时点沿用该活动现有逻辑。活动配置的角标文案
2充值返现角标该存款方式的充值返现生效（已在「充提返现设置 — 充值返现」中添加且状态开启），见《充值返现 PRD》第六章。「+N%」
3推荐角标该存款方式「是否推荐」开启。该存款方式的角标文案
—无角标以上均不成立。—

示例：pix_bestpay 同时开启推荐（角标文案「Rápido」）与充值返现 2%，且在进行中的限时充值返利中「推荐」为是。会员满足活动角标展示条件时显示活动角标；活动角标撤下后显示「+2%」；充值返现关闭后显示「Rápido」。

5.3 取款页：角标优先级

限时充值返利不作用于取款页。每个提现通道的渠道按钮按下表判定，规则同 5.2：

优先级角标显示条件内容
1提款返现角标该提现通道的提款返现生效（已在「充提返现设置 — 提款返现」中添加且状态开启），见《提款返现 PRD》6.1 节。「+N%」
2推荐角标该提现通道「是否推荐」开启。该提现通道的角标文案
—无角标以上均不成立。—

5.4 快捷档位角标

快捷档位右上角是否显示角标、显示哪一类，跟随当前选中渠道的渠道角标类型：渠道按钮按 5.2 / 5.3 判定出哪一类角标，快捷档位就显示该类对应的档位角标；渠道显示推荐角标或无角标时，快捷档位不显示角标。推荐角标只出现在渠道按钮上，不出现在快捷档位上。

页面当前渠道的渠道角标快捷档位角标
存款页限时充值返利角标显示限时充值返利的档位角标，内容与显示规则沿用该活动现有逻辑；不显示充值返现的「+N%」。
充值返现角标全部档位显示「+N%」，规则见《充值返现 PRD》第六章。
推荐角标 / 无角标不显示。
取款页提款返现角标全部档位显示「+N%」，规则见《提款返现 PRD》6.2 节。
推荐角标 / 无角标不显示。

切换渠道后，快捷档位角标按新渠道的渠道角标类型重新判定与显隐；限时充值返利角标撤下、渠道角标顺延为充值返现角标时，快捷档位同步改为显示「+N%」，顺延为推荐角标时快捷档位角标随之隐藏。

5.5 配置读取时机

与充提返现角标一致，前台不做实时推送，在进入钱包页、切换存款 / 取款 Tab、切换渠道、刷新页面时重新读取推荐配置并重新判定角标。会员停留在页面期间后台修改推荐配置的，页面不自动更新。限时充值返利角标按该活动现有逻辑撤下后，该渠道按钮立即按本章优先级顺延显示下一级角标。

本需求不新增前台固定文案：推荐角标内容由运营在后台录入，前台原样展示，不做翻译。后台界面为中文单语，下列新增后台文案不涉及葡语。

位置中文Português来源

七、边界与异常处理

场景处理方式
存款方式 / 提现通道被禁用推荐配置保留；前台不展示该渠道，角标随之不显示。重新启用后按保留配置显示。
存款方式 / 提现通道因会员等级、会员标签、解锁条件等规则对当前会员不展示渠道不展示，角标随之不显示；推荐配置不影响渠道的展示范围。
推荐开启，同时充提返现生效渠道按钮与快捷档位均显示「+N%」，推荐角标不显示；返现关闭或删除后渠道按钮顺延显示推荐角标，快捷档位角标随之隐藏。
仅开启推荐（无限时充值返利、无充提返现）渠道按钮显示推荐角标，快捷档位不显示角标。
推荐开启，同时被限时充值返利角标占用（存款页）显示限时充值返利角标；活动角标撤下后按 5.2 顺延。
限时充值返利中该存款方式「推荐」为否不满足优先级 1，顺延判定充值返现角标与推荐角标。
同一会员同时存在多个进行中的限时充值返利是否显示及显示哪个活动的角标文案，沿用该活动现有逻辑；本需求只判断限时充值返利角标是否显示。
充值返现 / 提款返现当日额度已用尽沿用《充值返现 PRD》《提款返现 PRD》：角标仍按比例展示（不做额度预检），因此仍占用角标位，推荐角标不显示。
多个渠道同时开启推荐各自显示推荐角标，不限数量，不互相影响。
历史数据上线时全部默认「否」、文案为空，前台无变化。
角标文案含表情符号或特殊字符不做限制，按 1 个字符计数，前台原样展示；显示效果由运营自行确认。
会员停留页面期间后台修改推荐配置页面不自动更新，按 5.5 的读取时机刷新。
保存并发冲突两名管理员同时编辑同一行时后提交者覆盖，操作日志各记一条，与所属页面现有规则一致。

八、权限

  • 不新增权限点。支付方式管理的推荐配置归属该页现有「添加 / 修改」权限；提现通道配置的推荐配置归属「提现管理」现有编辑权限。
  • 仅有查看权限的账号可在列表中看到「推荐」「角标文案」两列，无法打开编辑弹窗，与所属页面现有规则一致。

九、关联需求同步说明
